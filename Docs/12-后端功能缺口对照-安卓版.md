## 1. 结论先说

**数据面不缺，控制面几乎全缺。**

安卓客户端把 mihomo 当成一整套可管理的配置系统：多 profile、导入/更新订阅、
点名选节点并记住选择、驱动测速、看连接并可强断、跟随网络变化换 DNS、热更 geodata、
灭屏挂起内核。我们目前只有一件外部脚本生成的 `config.yaml`、一条隧道、
和一排**只有 debug 文本入口、产品入口为零**的运行时能力。

一句话：**能把流量送出去，但用户没法"用"它。**

前台按钮 4 个（`MainComponent.cs:43-46`：计数/重建/连接/断开），
状态文本一个动作后写一次；`settings.txt` 的 15 个开关只有插件读、
前台既不能写也不显示（`LocalSettings.cs:365-393`）。
也就是说：**当前形态下改任何行为都要手编文件**，这不是产品，是实验台。

## 3. 几条值得单独说清的

**G2 是全场性价比最高的一条，而且比原先估计的还便宜。** §7 实测：
`PUT http://127.0.0.1:9090/proxies/{组名}` + body `{"name":"节点名"}` ⇒ **204 即切换成功**，
`GET /proxies` 里读 `now` 就是当前选择；**选择由内核自己持久化到 `<home>/cache.db`**
（硬杀进程再起来，选择还在）。所以我们不用写 `selections.txt`、不用做安卓 `SelectionDao`
那套回灌 —— 那是安卓被迫自己存的原因（它的内核在另一个进程里、home 不同）。
剩下的工作量只在**渲染分组树**（`GET /proxies`，注意内置的 `GLOBAL/PASS/REJECT/…` 要滤掉）
和**给 UI 一个入口**。
**但有一个前置**：`cache.db` 落在 home，而我们的 home 是只读包目录（G10）
⇒ **先修 G10，否则选节点会"当场生效、下次没了"**，还静默。
**另注意它与排除路由的耦合**：选了别的节点 ⇒ 该节点的 `server:` 必须在
`Ipv4ExclusionRoutes` 里；`NodeRoutes.cs` 是从整份 `config.yaml` 提全部 IP 的（上限 240 条），
所以"订阅内任意手切"现在是安全的 —— 一旦将来把排除路由收窄成"只排选中节点"，这两处必须一起改。

**G6 是"看起来没坏、其实是运气"的一类。** 安卓明确处理了"换网络 ⇒ 系统 DNS 变了 ⇒
喂给内核"和"链路消失 ⇒ 内核 DNS 清空"，我们一条都没有。现在能连，是因为
fake-ip 池 + NRPT 把解析权收进了隧道，物理 DNS 变了不影响隧道；
但**出站网卡绑定**（`interface-name`）换网络就作废，而它只有 debug 入口、无人驱动。
这条要落地必须先确认一件事：Windows 上 `NetworkChanged` 事件在 vpnClient 后台任务
进程里到底能不能收到（文档级结论，未实测）。

**G10 顺手就能修，但不修会咬人。** `SetHomeDir(InstalledLocation)` 意味着
mihomo 的 home 是只读包目录。今天 GEOIP 能命中，是因为 `Country.mmdb` 恰好随包打了进去
（`ClashUWP.csproj:116` Content）；一旦订阅里出现 `proxy-provider`/`geodata` 需要落盘，
就是静默失败。把 `Country.mmdb` 复制进 `LocalState`（首启用 `Copying` 属性）
并把 home 指过去，同时得到"geodata 可更新"。这条与 G11 是同一个根因。

**G5 是真的做不到，不是没做。** 桥 ABI（`MihomoBridge.cs:31-52`）只有 start/stop，
没有 `suspend`/`reset`；Go 侧要新增导出并在 mihomo 里找对应入口。
本机没有 Go 工具链和 gcc，`clash_bridge.dll` 编不出来（Docs/05 §3 同一条约束）。
装工具链属于改用户机器，未获同意不动 ⇒ **这条只能挂着**。

**G12 要先于所有功能，但它缺的不是闸，是门控。**
Docs/09 记的 P1/P2（探测收尾绕过闸、同一份代码里两种拆法）**已经修掉了** ——
本次复核：`StartupProbes.cs:215-216` 拿到 `tornDown` 才 `DeleteProfileAsync`（`:244`），
`VpnProfileSetup.cs:422-428` 的 `DeleteByNameAsync` 先过 `EnsureSessionTornDownAsync` 再删，
不确认就 `profile-delete-refused` 拒绝。也就是说"拆 VPN 拆出整机断网"那个入口
在代码层面已经封住。

真正还开着的是**自动拨号没有门控**：`Diagnostics.cs:46` 首次启动就把
`RunProbeOnceAsync → RunDatafaceProbeOnceAsync` 串上，后者自建 `ClashUWP-Dataface`、
自己 `ConnectProfileAsync`、自己断、自己删，唯一判据是 `dataface-v4.txt` 存不存在
（`StartupProbes.cs:70`）—— 那是**装包后第一次启动必然满足**的条件。
在给用户加"选节点/切 profile/订阅更新"之前，这件事要先收口：
探测应该由用户点一下、或由一个可见的设置项允许，而不是默认发生在第一次开机。
否则每加一个入口，就多一条"用户没要求却动了整机网络"的路径。

## 4. 明确**不算**缺口（架构差异，写下来防止重复排查）

| 安卓有 | 为什么我们不需要 |
| --- | --- |
| `tunStackMode`（system/gvisor/mixed，`ServiceStore.kt:59-62`） | 我们把内核 TUN 强制关掉（`KernelConfig.cs:185-258` → `tun.enable:false`），L3 由 Windows VPN 平台承担。stack 概念在本架构下**不适用** |
| `protect()` 逐 socket 绑物理网卡（`TunModule.kt`，`tun.go` 注释 `AutoDetectInterface: false // implements by VpnService::protect`） | Windows VPN Plugin 平台无 per-socket 原语（Docs/05 §1 已穷举类型清单）。已用 `/32` 排除路由 + `interface-name` 两道替代防线 |
| `setHttpProxy`（`TunService.kt:129-139`，靠 `listenHttp()` 现开一个 HTTP 监听，`TunModule.kt:49-52`） | 安卓用它兜"不遵守 VPN 的应用"。我们是 L3 全接管，不需要应用配合。真要做只能改 WinINET/WinHTTP 代理，那是**另一条数据通路**，不是缺口修复 |
| `allowBypass()`（`TunService.kt:141-143`） | Windows 侧等价语义 = NRPT/trafficFilter 不参与某些进程，已有 `selfSplitTunnel` 的实验形态；平台不支持"会话级放行" |
| `setUnderlyingNetworks` | 注意安卓自己也只在 `SDK_INT in 22..28` 用（`TunService.kt:26`），现代版本靠 `protect()`。我们对应物是 `interface-name` |
| `Clash.load()/reset()` 的进程内 golang bind | 我们走 `clash_bridge.dll` + REST 控制器；常驻是 Docs/05 §2④ 为绕开"二次 Start TLS 回不来"刻意选的，不是遗漏 |

## 5. 建议顺序（原则：先做不碰隧道、不需要实测授权、且能自证的）

1. **G12 启动自动探测加门控** —— 收尾闸已全线封住，剩下的是"第一次开应用就自动拨 VPN"这件事该由用户决定（防事故优先于加功能）。**★ 已落地：§9.1**
2. **G10 home 迁到 `LocalState`**（顺序按 §7 实测调整）—— 一行方向的修正，但它同时是
   GEOIP 可更新、provider 可落盘、**选择可持久**（`cache.db`）三件事的地基，不做它 G2 就是半截功能。**★ 已落地：§9.4（与热重载同批）**
3. **G2 选节点** —— `PUT /proxies/{组}` + `GET /proxies` 渲染分组树，持久化白捡；成本最低、体感提升最大。**★ 已落地：§9.2（调试通道形态，UI 待 G8）**
4. **热重载改 JSON body**（§7 已证 query 形态必 400）—— 换订阅不拆隧道，与 G1/G11 同一个开关。**★ 已落地：§9.4；★ 更正见 §7.2 —— 光改 body 不够，第二把锁是 `IsSafePath`**
5. **G8 模式切换与生效值回读进 UI**、**G3 周期状态采集** —— 复用 G2 的渲染层；顺带把 15 个 `settings.txt` 把手变成可见设置（前台目前无 writer）。
6. **G1 订阅导入/多 profile** —— 依赖 2（落盘）与 3（选择），放一起改才不返工。
7. **G6 网络变化跟随** —— 先写一个"只记日志不动作"的探针验证事件在 vpnClient 进程可达，再决定接线。
8. **G4 连接视图/强断** —— 有了 3 的状态通道就是顺手。
9. **G11 provider/override** —— 与 G1 同批。
10. **G7 IPv6** —— 碰隧道，需要授权实测；判据用先遣项目的 2000::/3 与四类判据（任务 #12）。
11. **G9 按应用分流** —— 原语齐备（§6），缺的是名单来源与 UI；先小测"能否拿到别的可执行路径"。
12. **G5 挂起/重置** —— 阻塞在 Go 工具链，需要用户同意装工具链才能开工。

## 6. "平台有没有原语"这一列是怎么查的

不靠印象，也不只靠 Learn 文档 —— 直接查本机 SDK 的 WinRT 元数据：


## 7. REST 语义：已用官方内核实测（推翻了一条项目记忆）

原来这张表里的动词是"按已知用法书写"。现在用**官方二进制**跑了一遍，结论可复现：

方法：`C:\Program Files\Clash Verge\verge-mihomo.exe`（Mihomo Meta **v1.19.32**，`with_gvisor`）
以 `-d .local/proxyapi` 起一份最小配置（`mixed-port: 7897` + `external-controller: 127.0.0.1:9097`
+ `allow-lan: false` + **无 tun** + 一个 `type: select, lazy: true` 的组 `测试分组`，
成员 = 订阅里三个真节点 + DIRECT，`rules: MATCH,DIRECT`）。
`lazy: true` + `MATCH,DIRECT` ⇒ 全程不拨号、不动系统路由；
事后核对：进程已退出、7897/9097 无 LISTENING、默认路由仍是 `0.0.0.0 → 192.168.0.1`。

| 实测项 | 请求 | 结果 | 结论 |
| --- | --- | --- | --- |
| 选节点用哪个动词 | `PATCH /proxies/{组}` | **HTTP 405**，`now` 不变 | **PATCH 不能选节点**（项目记忆里写的就是这条，错） |
| | `PUT /proxies/{组}` body `{"name":"…"}` | **HTTP 204**，`now` 立刻变成节点名 | ★ **只有 PUT 生效** |
| 组结构 | `GET /proxies` | 字段是 `now`（不是 `selected`）、`all`、`history`、`type`；内置条目 `GLOBAL/PASS/REJECT/REJECT-DROP/COMPATIBLE/DIRECT` 同表返回 | UI 渲染按 `now` 读当前选择 |
| 中文组名 | 路径里原始 UTF-8（不编码）`PUT /proxies/测试分组` | HTTP 204 且**确实生效**（`now=DIRECT`） | PUT 这条路能吃原始 UTF-8；记忆里"必须编码"的坑是 **带 query 的 `GET /proxies/{name}/delay`**，两种形态别混。代码里统一编码，不赌 |
| 热重载 | `PUT /configs?path=…&force=true`（path 只在 query） | **HTTP 400** | ★ 这就是 `MihomoController.cs:16-19` 断言"从来没生效过"的**现场复现** |
| | `PUT /configs` body `{"path":"…","force":true}` | **HTTP 204**，日志出现 `Initial configuration complete` + provider 重启 | ★ 换订阅的正确形态，一个 body 之差；**但这条里 body 的 `force` 其实没人读**，见 §7.2 |
| 热重载会否冲掉选择 | 先选节点再热重载 | `now` **保持** | 不需要像安卓那样回放 `SelectionDao` |
| 选择存哪 | 改选择 → `taskkill /F` → 重启进程 | `now` **仍在**；目录里只多出 `cache.db`，`grep` 到 `selected` 键与节点名 | ★ 持久化由**内核**做，落 **`<home>/cache.db`**，不是我们写文件 |
| embed 模式限制 | 读 mihomo `Meta` 与 CMFA `patch_android.go` | 安卓那份 `SetEmbedMode(true)`，**禁掉** `PUT/PATCH /configs`、`POST /configs/geo`、`PATCH /rules/disable`、`POST /restart`；我们 `Tools/mihomo-bridge` 全量 grep **没有** `SetEmbedMode`（只命中 `SetHomeDir`） | 这些端点我们这侧是开着的 —— 安卓做不到而我们能做的恰好是热重载 |

### 7.1 第二轮：写 `groups`/`select` 之前把返回形状钉死（又推翻两条想当然）

上一轮的表说的是"动词"。这一轮要的是**解析口径**，两条都不对：

| 实测项 | 请求 | 结果 | 结论 |
| --- | --- | --- | --- |
| 成员列表的形状 | `GET /proxies` 与 `GET /proxies/{组}` 的 `all` | **两个端点都返回字符串数组**（`typeof all[0] === "string"`，样例 `"DIRECT"`） | ★ "只有组详情接口才把 `all` 展开成对象"是**错的**。为拿成员明细逐组多打一次接口是白做的 —— 一次 `GET /proxies` 就够 |
| 测速历史挂在哪 | `GET /proxies/DIRECT/delay?timeout=3000&url=http://www.baidu.com` → `{"delay":5}`，再 `GET /proxies` | `proxies["DIRECT"].history = [{time,delay:5}]`；而**组的 `history` 始终是 `[]`** | ★ 延迟要按**成员名去顶层条目查**（`proxies[节点名].history`），不是去组的 `all` 里找对象字段 |
| 内置策略到底有没有 `all` | `GET /proxies` 全表 | `COMPATIBLE/DIRECT/PASS/PASS-RULE/REJECT/REJECT-DROP` 的 `type` 是 `Compatible/Direct/Pass/PassRule/Reject/RejectDrop` 且**没有 `all`**；唯一混进来的是 **`GLOBAL`（`type=Selector` + `all[6]`）** | 结构判据（type ∈ 可切换四型）能挡掉大多数内置策略，但**GLOBAL 必须按名字排除**；类型名的驼峰形态（`Selector` 而非 `select`）实测确认 |
| 未测速时的 `alive` | `GET /proxies`（`lazy: true`，全程没拨过） | 每个条目都 `alive: true`，`history: []` | 印证 §7 的"选择存哪"那条：`alive` 在测过之前不可信，`groups` 输出里不列它，只列 `delay`，没测过明写 `-` |

**⇒ 代码落成了什么样**：`ReadProxiesTable()` 一次 `GET /proxies` 同时产出「可切换组（含成员名）」+「每个节点最近一次 delay」，
`groups` 与 `select` 都只依赖它，各自**总共一次读 + （select 另加一次 PUT 与一次回读）**。

**由此改掉的三条（上面表格里的 G2/G10 已同步修订）：**

1. **G2 的实现形态变了**：不用自建 `selections.txt`，只要 `PUT /proxies/{组}`（204 即成功），
   "记住选择"由内核 `cache.db` 负责。
2. **G10 从"顺手修"升级成 G2 的前置**：`cache.db` 建在 **home 目录**，而我们把 home 设成了
   `Package.Current.InstalledLocation.Path`（只读包目录，`ClashVpnPlugin.cs:1490-1492`）
   ⇒ 选节点会"当场生效、下次没了"，而且是**静默**没的。先修 home，再谈选择。
3. **热重载有救**：`TryHotReload`（`ClashVpnPlugin.cs:1625`）把 path 拼在 query 上，
   官方内核直接 400；改成 JSON body 就 204。这条与 G1/G11 是同一个开关。

**顺带量到的一条线索**（关于 §8 那个仍未验的控制器问题）：宿主侧 `netstat` 能看到
`ClashUWP.exe` 在 `127.0.0.1:9090 LISTENING`，但从包外 `curl /version` **超时挂住**（不是拒绝）
⇒ 与 AppContainer 回环隔离一致，**判据只能在包内取**（`debug-cmd controller`）。
这条同时说明：**别把控制器当安全边界**，包外不可达靠的是隔离，不是 `secret`（我们请求不带 secret）。

### 7.2 第三轮：把 `PUT /configs` 的两个参数位置按源码钉死（★ 更正 §7 那行）

官方二进制能测出"哪种写法 204"，测不出"为什么另一种 400"。这一轮读的是
**我们桥里 pin 住的那一版**源码 —— `Tools/mihomo-bridge/go.mod` pin 的就是 `v1.19.32`，
与 §7 用的官方 `verge-mihomo.exe` **同版本号**（`Mihomo Meta v1.19.32`），所以这份源码
对我们的行为就是权威口径，不存在"官方版本不同"的推脱空间。

`hub/route/configs.go` 的 `updateConfigs`：

```go
req := struct {
    Path    string `json:"path"`
    Payload string `json:"payload"`
}{}
if err := render.DecodeJSON(r.Body, &req); err != nil { ... }   // ⇒ path 只能来自 JSON body
force := r.URL.Query().Get("force") == "true"                   // ⇒ force 只能来自 query
```

⇒ 三条结论，其中第一条是对 §7 那行的**更正**：

1. **§7 表里"body {path,force} → 204"其实是 `force=false` 下重载成功的** —— body 里那个
   `force` 键根本没有对应的结构体字段，`json` 解码时被人丢弃。也就是说：官方内核接受并
   执行了那次重载，但走的是"非强制"分支。**正确形态是参数分属两个位置**：
   `PUT /configs?force=true` + body `{"path":"<绝对路径>"}`。
2. **老代码 400 的机制终于有了原文**：`req.Path == ""` 时代码回落到 `C.Path.Config()`
   （home 里的 `config.yaml` —— 我们没有那份文件），于是报 "path is not a absolute path"
   一类错误。§7 只测出了"query 形态必 400"这个现象，没解释为什么。
3. **还有第二把锁，而且这把锁 G10 不解就打不开**：`path` 给了绝对路径之后，内核查
   `IsSafePath(path)`，而 `constant/path.go` 里 `SafePaths() = [homeDir] + SAFE_PATHS 环境变量`。
   ⇒ **只有 home 之内的路径才允许被热重载**。放行它的另外两条路我们都不占：
   CMFA 构建标记（`features.CMFA`）没有，`allowUnsafePath` 也没有
   （`Tools/mihomo-bridge` 全量 grep 只命中 `SetHomeDir`，没有 `SetEmbedMode`）。
   而改写后的订阅配置就写在 **`LocalState`**（`KernelConfig.EffectiveFileName = config.kernel.yaml`），
   home 原先在**只读的包安装目录** ⇒ 我们的 path 永远不在 safePaths 里，**必然 400**。

这三条落成的代码就是 §9.4：`TryHotReload` 改成 `?force=true` + 手写转义的 body，
home 由新增的 `KernelHome` 迁到 `LocalState`。**两把锁属于同一批改动，拆开上等于白改。**

### 9.1 G12 —— 自动探测改成"用户授权才拨"

| | 改前 | 改后 |

★ 刻意不复用组件里的 `LocalSettings.Load()` —— 那个为了在 WinRT 同步回调里用，
走的是 `AsTask().GetAwaiter().GetResult()` 的同步等异步，而 `Diagnostics.StartOnce()`
是在 `MainComponent.Render()` 的**渲染线程**上点火的。代价是同一个文件两份解析器，
所以布尔真值表**逐字照搬**了 `LocalSettings.ReadBool`（`1/true/on/yes`、`0/false/off/no`、
其余回落），两边不许分叉。

顺带修掉一个装配毛病：原来两个探测用 `RunProbeOnceAsync().ContinueWith(_ => …)` 串，
内层任务没人 await（异常掉进未观察任务），且 `ContinueWith` 默认 `TaskScheduler.Current`
可能把探测甩回 UI 调度器。现在是一个 async 方法里两个 `await`，串行语义不变、两个毛病都没了。

### 9.2 G2 —— `groups` + `select` 两条调试命令（选节点的最小可用通道）

- `MihomoController.RunGroupsAsync()`（`debug-cmd groups`）：一次 `GET /proxies` 列出
  可切换组、当前 `now`、成员名，成员延迟按 §7.1 的口径从**顶层条目**的 `history` 查；
  没测过明写 `delay=-`（★ 不等于挂了），不列未测速时不可信的 `alive`。
- `MihomoController.RunSelectAsync()`（`debug-cmd select <组名> <节点名>`）：
  ★ **`PUT /proxies/{组}` + body `{"name":…}`**（§7：PATCH 在这条 URL 上是 405）。
  三道口径：**先校验成员名真在该组里**（不在就把前 12 个成员原样回出来供照抄）、
  **组名进 URL 一律 percent-encode**、**回读 `now` 才算成功**（204 本身不证明选上了）。
  参数里第一个空格前是组名、其余全算节点名，所以带空格的节点名可以照抄；
  只给一段时当作节点名，并在"只有一个可切换组"时自动补组名（多个组则报错列组名，不猜）。
  内置策略名被单列出来告诉用户"那是内核策略，不是组"。
- 自动组（`URLTest`/`Fallback`/`LoadBalance`）额外提示：PUT 会被接受，
  但下一轮测速/故障转移会把名字改回赢家 —— 别读成 select 失败。
- JSON body 手写转义（`JsonEscape`）：Native AOT 里 `JsonSerializer.Serialize` 直接抛

| 失败口径 | —— | **退回包目录**并记 `home=包目录 退回原因=…`。GEOIP 规则在 `config.Parse` 阶段就要读 MMDB（`Tools/mihomo-bridge/bridge/core.go:127-128`），⇒ **宁可丢掉持久化这个新功能，也不给已经能连的数据面添一条新的失败路径** |

| 热重载可见性 | 只进 `_bridgeDiag`（要等下一次会话快照落盘才看得到） | 状态码 + **非 2xx 的响应原文**（≤200 字）同时进 `plugin.log` 的 `hot-reload` |

**解掉的是同一个功能的两把锁**（§7.2）：`path` 只能从 body 来（第一把），
`IsSafePath` 只放行 home 之内的路径（第二把，靠 G10）。
所以 §5 把 G10 排第 2、热重载排第 4，实际落地是**同一批** —— 拆开上等于白改。

顺带一并解决的：`cache.db` 选节点持久化（G2 的前置）、provider / rule-provider 落盘（G11 的前置）、
`GetPathByHash` 的写入位置。GEOIP 更新（`POST /configs/geo`）在安卓侧被 embed 模式禁掉，
我们这侧因为 `SetHomeDir` 可写，理论上也就不再被"目标不可写"卡住 —— 这条属于**推论，未验**。
