# 66 · 默认窗口宽度下按钮点不着（导航栏写死展开态）+ 内核读数补「本轮没答」档 — 1.0.125

这批两条都**不是新加的想要**，是 1.0.124 功能拨号实测（Docs/65 §4.1）当场产出的实物缺陷：
一条是界面把「断开 VPN」画成零尺寸、鼠标点不着；一条是拆隧道那几十秒界面上凭空冒出一句
「内核：未连接」。两条的判据都能在装机前钉死或眼看，下面按「实物 → 根因 → 修法 → 验证」记。

## 一、实物（1.0.124.0，772×985 窗口，UIA 逐字量出来的）

| 状态 | 导航栏 | 正文列 | 「VPN 控制」三枚按钮 |

★ 结论就在这张表里：**同一枚按钮在同一条 HStack 里，收起栏子就有尺寸、展开栏子就归零**

## 二、根因

### 1) 导航栏：我们把框架的响应式默认**关掉了**

`MainComponent.cs` 的 `NavigationView(...)` 显式传了 `paneDisplayMode: NavPaneDisplayMode.Left`。
`Left` 的含义是「永远保持展开态」，不是「放在左边、宽度随窗口」。而 Reactor 那条工厂的
参数默认值本来就是 `NavPaneDisplayMode.Auto`（反编译 `Factories.cs` 的签名可查），
Auto 才是框架自己的默认：窄窗口先收成图标栏，够宽才展开。

本包为什么会写死成 `Left`？—— 那一行上面没有任何注释交代理由，也就是说它不是被论证过的
选择，只是当初把"侧边栏"表达成 `Left` 的顺手写法。展开态的导航栏实物宽度是 **480 物理 px
= 320 DIP**（本机 150% 缩放），772 的窗口里正文只剩 268 物理 px ⇒ 只要窗口不超过
约 1440 物理 px，正文列就一直处于"三枚按钮放不下"的区间。

### 2) 内核读数：只有两档，把「没问到」并进了「没连上」

`KernelView.LoadAsync` 的三路查询（`/configs`、`/proxies`、`/connections`）任何一路抛异常
都只写一个 `error` 串，UI 那边 `if (!s.Ok) → "内核：未连接（…）"`。问题在于这两类失败
在实物上根本不是一回事，而且这个区别**早就写在本文件的注释里**（1.0.118 那段：
「回环端口关着是瞬时拒绝」）：

- 端口**关着** ⇒ 立刻 `HttpRequestException`（拒绝连接）⇒ 「内核没在跑」这句话有据；
- 端口**开着而对面不回话** ⇒ 走满 10 秒超时 ⇒ `TaskCanceledException`
  （内层常是 `TimeoutException`）⇒ 这一轮**什么都没问到**，内核可能正在启动、
  也可能正随隧道收尾。

拆隧道那几十秒恰好落在第二类，于是界面上出现一句无据的「未连接」，下一拍内核答上来又自己
消失。代理页顶部的来源横幅（1.0.118 立的三态判据，含「首轮未归不许谎报成没有」那条）
其实已经有同一个原则，但只有两档的主页读数没跟上，横幅自己也漏了「超时」这一档。

## 三、修法

1. **`MainComponent.cs`**：`paneDisplayMode` 从 `Left` 改回框架默认的 `Auto`。
   收成图标栏这一档在本包是可用的：四个条目本来就各带一个**从官方 WinUI-Gallery
   的 `IconsData.json` 逐条查出来的** Segoe MDL2 字形（主页 `E80F` / 代理 `E774` /
   订阅 `E896` / 设置 `E713`，见 `MenuItems` 那条注释），收起后靠图标认得出是谁。
   两个阈值参数（`compactModeThresholdWidth` / `expandedModeThresholdWidth`）**没传** ——
   框架默认 641/1008 DIP 的分档就是标准 WinUI 应用的形状，本包没有理由另立一档，
   传了就是"为假想需求调参"。
2. **`KernelView.cs`**：判据放在后端而不是 UI 里嗅字符串。
   - 新增 `internal static bool IsNoAnswer(Exception)` —— 只认异常类型
     （`TaskCanceledException` / `OperationCanceledException` / `TimeoutException`）；
   - `Snapshot` 新增 `bool QueryTimedOut = false`，由 `LoadAsync` 在失败返回时带上；
     ★ 默认必须是 `false`：`Failed()` 那条正常空态路径不许自称超时，否则每个"端口关着"
     的空态都会改口说"没问到"，判据反过来骗人。
   - 为什么不从 `Error` 串里找 `TaskCanceledException` 这个名字：那段文本是给人看的，
     改一个字的措辞就让界面分档静默失效 —— 这条纪律在 `KernelView` 文件顶部已经写着
     （「让 UI 去正则解析文本 = 把格式当契约」）。
3. **`MainComponent.cs` 的两处措辞按档分开**：
   - 主页 `KernelStatusPanel`：首轮未归 → `内核：正在查询…`；超时 →
     `内核：本轮没问到（查询超时，约 3 秒后自动重试）`；其余（含端口关着）才 →
     `内核：未连接（{原因}）`。原始 `Error` 只在最后一档带上，仍然不画空白或报错堆。
   - 代理页来源横幅：在「首轮未归」和「内核未运行」之间插入超时那一档，
     明确「下面是配置视图，来自磁盘、不代表内核活着」，并给出下一步（约 3 秒自动重试）。
4. **流量那一行没改**：它写的是「速率 读不到（内核不可达）」——「这一轮没够到它」在超时
   那一档也是真话，不存在替内核断言状态的问题；改它属于把同一句话拆成两种说法，不值。

## 六、遗留

1. **`HStack` 不换行**：本批只把宽度让回来，没有把三枚按钮改成会折行的排布。
   ★ 但装机把"可达的窄"量到底了：平台给本包的最小窗口是 **520 DIP**，那一档正文 758 物理 px，
   三枚按钮（自然宽度合计约 442）仍然放得下 ⇒ **现有按钮数量下没有会裁的窗口宽度**。
   这条留下的真正适用条件是"**以后往这一排再加按钮**"：`HStack` 是单行不换行的横排，
   加到约 4～5 枚就会重新出现"裁掉的那几枚点不着"（与本批同一条失效形状）。
   真要治得选一个会折行的容器（框架有 `WrapGrid`，但它是等宽单元格，
   三枚按钮文字长短不一，套上去不好看），或者按宽度分档换 `VStack` —— 等第四枚按钮出现时再做。
2. **同族的另一处措辞**：测速按钮（`HealthCheckAsync`）与「内核实时日志」按钮在 `!Ok` 时
   回一句「内核未运行：……」。那两条走的是**当场拒绝动作**，动作本身在超时档也是对的
   （REST 这一轮不会答），但话术上同样替内核断言了"没在跑"。本批没动，留着按同一判据改。
3. 导航栏展开态 320 DIP 这个宽度是框架给的，本包没有可拧的旋钮
   （`NavigationViewElement` 这条记录里没有 `OpenPaneLength`）；如果将来正文要更宽，
   得走"页面内自己排两栏"而不是继续调导航栏。
4. **同一页还剩一处同族措辞**（★ 这一轮装机当场看到的，不是推演）：主页在超时稳态下
   两行并排互相矛盾 —— `lbl-3-5ac8「内核：本轮没问到（查询超时，约 3 秒后自动重试）」`
   和下面活动连接列表的 `lbl-5b3b「(内核未连接)」`。后者来自
   [ClashUWP/Frontend/MainComponent.cs:1640](file:///D:/fluentapps/repos/ClashUWP/ClashUWP/Frontend/MainComponent.cs#L1640)
   的 `if (!s.Ok) return TextBlock("(内核未连接)")`，和本批修掉的那两处是同一个"把问不到说成没在跑"。
   修法就是复用同一个 `s.QueryTimedOut`（一行的事），本批没动的原因不是遗漏：
   改界面文案必须重新出包，而**同版本号升级装机会撞 `0x80073CFB`**（见 [[Same-version reinstall 0x80073CFB]]），
   要么 bump 到 1.0.126 再起一轮完整取证 ⇒ 和 §六 2 那两条攒成下一批一起做。
5. **超时档在 `residentBridge=1` 下是稳态而不是过渡**（本表 4b 的那次实测）⇒
   界面承诺的「约 3 秒后自动重试，内核答上来这一段自己消失」在会话拆掉之后**永远不会兑现**，
   用户看到的是"卡在没问到"。诚实的措辞要么补一句"若已结束会话，这一档会一直停在这里"，
   要么把"有没有活动会话"（前台读得到平台状态）也喂进分档 ——
   本批的 `QueryTimedOut` 只是一个布尔，分不出"正在启动"和"已拆完但内核随宿主常驻挂起"，
   加这一维要先定"读哪个状态、多久读一次"，不在本批范围内。
