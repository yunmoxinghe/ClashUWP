## 2. 缺口是什么形状

旧行为（1.0.70 及以前）里，"DNS 能配"的入口只有两个，而且都不是给用户用的：

1. **订阅原文**里的 `dns:` 块 —— 想换 `nameserver`/`fallback` 得改订阅或改 YAML，
   改完还要自己保证不把内核的解析校验碰坏；
2. **profile 的 CustomConfiguration** `<dns>` 清单 —— 只在重建系统 profile 时写入，
   是"装包时决定的"，不是"运行时能调的"。

这留下三个具体问题：

- 国内网络下想换成 `223.5.5.5` / DoH，没有入口；
- 想调 `fake-ip-filter`（哪些域名**不**给假 IP）没有入口，而它直接决定
  "某些应用能不能直连命中真实 IP"；
- `fake-ip-range` 在项目里有**三个读者**（内核 YAML、窄 include 路由、会话看门狗判据），
  此前是写死的 `198.18.0.0/16`。用户即使自己改订阅 YAML，后两个读者也不会跟着走
  —— 典型的"以为在代理、其实直连"或"好隧道被看门狗判死"。

本功能只解决"DNS 这几个键可调"，不把整个 `dns:` 块开放给用户手写 YAML ——
理由在 §4 与 §8：内核的 `parseDNS` 有**一整排会直接让整份配置解析失败**的校验，
而配置解析失败在本项目等于 `failFast` 放弃连接。宁可少给几个键，也不能给一个
"改一行就连不上 VPN"的入口。

## 3. 文件与语法

文件：`%LOCALAPPDATA%\Packages\<包族>\LocalState\dns-config.txt`

```text
# 一行一条：key = value，# 开头是注释
nameserver = 223.5.5.5, 119.29.29.29
fake-ip-range = 198.18.0.1/16
fake-ip-filter = *.lan, +.msftconnecttest.com
nrpt-dns = 223.5.5.5, 119.29.29.29
```

- **键大小写不敏感**（归一小写）；值去掉首尾空白。
- **同名键后写的赢**（与 `settings.txt` 同口径）。
- **空值一律拒绝**：`nameserver =` 在内核眼里是"显式的空列表"，不是"不改"
  （`parseDNS` 会因为 `dns.enable` 为真而 `nameserver` 为空直接报错）。
- 文件最多 **40 条**有效项，超出部分整段忽略并记一条拒绝原因。
- **总闸**：`settings.txt: dnsConfig=0` 时整个文件不读，内核与 NRPT 都不动；
  默认 `1`。

### 3.1 为什么单独一个文件，不塞进 `settings.txt`

`settings.txt` 是本项目唯一的**取证通道**：每一轮 `channel=settings` 的那行日志
是整批实验臂的判据。前台 writer 一旦写坏一行，连坐的是一整批开关。
⇒ 每个新功能自带一个文件、自带一个 writer（与 `split-apps.txt` 同一条纪律，见 Docs/20 §3.1）。

### 3.2 为什么前台保存的是原文

`dns-config.txt` 的头部注释就是使用说明，用户很可能在上面记自己的备注；
应用分流的规则行是结构化产物，而 DNS 这份是"一行一个键值"的配置文本。
⇒ 保存**原文写回、不丢注释**，代价是不替用户规范化拼写；被拒绝的行会在保存结果里
逐条列出来（不静默）。

## 4. 白名单与逐条校验（照 mihomo v1.19.32 源码）

`DnsConfig.Validate` 的每一条都对着 pin 住的内核源码写（行号在本机
`go/pkg/mod/github.com/metacubex/mihomo@v1.19.32` 现读）：

| 键 | 规则 | 内核依据 |
|---|---|---|
| `enhanced-mode` | **只接受 `fake-ip`** | `config.go:1508` 两种都认；但本项目的窄 include 路由、看门狗判据②、域名流量进隧道全建立在假 IP 上 —— 放行 `redir-host` 会得到"能启动、30 秒后被看门狗判死"的配置 |
| `fake-ip-range` | IPv4 前缀 | `config.go:1488-1495`：`netip.ParsePrefix` + 必须 `Is4` |
| `fake-ip-range6` | **ULA（`fc00::/7`）且前缀长 48~64** | `config.go:1498-1505` 只要求 `Is6`；本项目更严，因为同一个值还要当 include 路由与 `tun.inet6-address` 的池子（G7） |
| `fake-ip-filter` | 域名清单，逗号分隔；每项 ≤200 字符 | 写进 YAML 行内流式序列；`'`、`,`、`\|`、控制字符会破坏 YAML，直接拒绝 |
| `fake-ip-ttl` | 1~86400 秒 | `dns/enhancer.go:185-187` 会夹到最小 1 |
| `default-nameserver` | 每条必须是**纯 IP**（`system` 例外） | `config.go:1466`：**与 `dns.enable` 无关，恒要求至少一条非空**；`:1473-1485` 要求纯 IP |
| `nameserver` / `fallback` / `proxy-server-nameserver` / `direct-nameserver` | 裸 IP、`system`、或 scheme 白名单 | `config.go:1202-1288`：裸 IP 由 `parsePureDNSServer` 补成 `udp://ip:53`；scheme 见下 |
| `ipv6` / `prefer-h3` | 布尔（`0/1/true/false/on/off/yes/no`） | `RawDNS` 字段 |
| `ipv6-timeout` | 0~60000 毫秒 | `RawDNS.IPv6Timeout`（uint） |
| `nrpt-dns` | 纯 IP 清单 | 不进 YAML；构造成 `HostName` 给 `VpnDomainNameInfo` |

**scheme 白名单**（`config.go:1225-1284`）：`udp` / `tcp` / `tls` / `http` / `https` /
`quic` / `rcode`。`rcode` 的主机名还必须是固定清单
`success | format_error | server_failure | name_error | not_implemented | refused`
（`:1272-1281`）—— 写错一个字母就是整份配置失败。
`ts:` / `tailscale:` / `et:` / `easytier:` / `dhcp:` **本版本明确不支持**：
它们要求目标 profile 存在，与"组名会随订阅变"是同一个坑（等组名校验做完再加）。

**为什么非法值必须在写文件之前挡掉**：内核任意一条校验失败 = 整份配置解析失败 =
桥 `start rc=-2` = `failFast` 放弃连接。所以：

- 保存时前台用**同一个** `DnsConfig.Parse` 回读并列出被拒行；
- 连接时插件再读一次，`channel=dns` 日志里给出 `Describe()` 与逐条拒绝原因；
- 诊断快照 `Dns=` 行给出"应用几项 / 跳过什么 / 拒绝几行"。

## 5. 实现（按文件）

### 5.1 `ClashUWP.Vpn/DnsConfig.cs`（新）

- 模型：`DnsEntry { Key, Value }`、`DnsConfig`；`Parse` 不抛，畸形行/未知键/非法值
  一律进 `Rejected` 并带原因。
- **派生值**（本类最要紧的设计）：
  - `FakeIpRange`（YAML 写法，默认 `198.18.0.1/16`）；
  - `FakeIpRoute`（网络号/掩码，如 `198.18.0.0/16`，窄 include 用）；
  - `FakeIpNetwork` / `FakeIpPrefix` / `IsInFakeIpPool`（看门狗判据②）。
  - 解析不出合法 IPv4 前缀时**退回默认池**——宁可用旧值，也不能让路由表空着。
- v6：`DefaultFakeIpRange6 = fdfe:dcba:9876::/64`（与 `LocalSettings` 逐字相同）；
  `EffectiveFakeIpRange6(fallback)` 让 `dns-config.txt: fake-ip-range6` 优先于
  `settings.txt: ipv6FakeRange`，归一化走 **同一把尺子** `TryNormalizeV6Prefix`。
- `Load()` 同步读（Connect 的同步回调里用）；`Describe()` 一行式结果；
  `ToText()` 生成带键说明的模板（文件不存在时前台直接显示它）。

### 5.2 `KernelConfig.Transform`：第三个输入面

签名从 5 参变 7 参：

```csharp
Transform(string yaml, AppSplit? split, DnsConfig? dns,
          int ipv6Arm, string ipv6FakeRange,
          out string splitNote, out string dnsNote)
```

`ApplyDnsOverrides` 在 `EnsureTunBlock` 之后、`LockUrlTestTolerance` / `InjectAppSplitRules`
之前执行，**按键增删**，不重写整个 `dns:` 块：

- **没有 `dns:` 块** → 正常路径走不到这里：`EnsureDnsBlock`（1.0.69 起的假 IP 基线）
  会先补一个最小 `dns:` 块，覆盖随即叠在它上面。`ApplyDnsOverrides` 里的
  `N 项未应用：配置里没有 dns 块` 只是防御分支，正常订阅不会出现。
- **`dns:` 是行内流式写法**（`dns: {…}`）→ 整块不动（沿用 G6 起的 YAML 安全取舍）。
- **已有键** → 只改这一行的值（保留原缩进与键的写法）；
- **缺失键** → 插在块尾，缩进取块内子键的缩进；
- **已有键但值为空**（块序列/块映射的父键，如 `nameserver:` 换行跟 `- …`）→
  跳过该键并写进 note（`nameserver(块写法，未替换)`），绝不留孤儿行。
- **`nrpt-dns`** → 不进 YAML，只计数（`nrpt-dns→NRPT×N`）。
- **`ipv6`** → `ipv6Arm ≥ 1` 时跳过：档 1/2 的 AAAA 开关是数据面安全属性，
  不接受 `dns-config.txt` 覆盖（归属权在 `settings.txt`）。
- **`fake-ip-range6`** → `ipv6Arm < 2` 时跳过；档 2 时用已经归一好的
  `ipv6FakeRange`（即本文件覆盖后的值）。
- **`enhanced-mode`** → 无论用户写什么（校验已只放行 `fake-ip`），一律写 `fake-ip`。
- **列表类键是整条替换**，不是追加：想保留订阅默认就把原值一起抄进来。
- 布尔键写 YAML 字面量 `true`/`false`（不是 `1`/`0`）；列表写成行内流式序列
  `['a', 'b']`。
- **每应用一条都重新定位 `dns` 块**：上一条可能已经插过行，行号不能复用。

`dnsNote` 是这条链路的证据句，例：
`应用 3 项（跳过 ipv6(由 settings 档位决定)、fake-ip-range6(需 ipv6=2)），nrpt-dns→NRPT×1，另拒 1 行`。
`fakeIp=0` 时整份改写关闭，`dnsNote = "fakeIp=0 → 整份改写关闭，DNS 覆盖未应用"`。

### 5.3 `ClashVpnPlugin`：一次读取，三处使用

- `Connect` 里 `LocalSettings.Load()` 之后：
  `_dnsConfig = LocalSettings.DnsConfigEnabled ? DnsConfig.Load() : new DnsConfig();`
  并计算 `_ipv6PoolEffective = _dnsConfig.EffectiveFakeIpRange6(LocalSettings.Ipv6FakeRange)`。
- `channel=dns` 日志：`读 dns-config.txt：…`（或 `总闸关闭(dnsConfig=0)，不读…`），
  档 2 时附 `v6pool=`；拒绝行逐条 `RollingLog.Warn`。
- 三个读者都吃**同一份** `_dnsConfig`（§6）。
- 会话日志新增 `dnsCfg={none|N项} fakePool=<生效 v4 池>`；
  `evt=start` 行带同样两个字段。
- 诊断快照：`DnsIntoTunnel=… (生效 DNS 清单) nrpt={dns-config 覆盖|profile}`，
  另起一行 `Dns={_dnsNote}`。

### 5.4 `SessionWatchdog`：判据跟着生效值走

`Start` / `LoopAsync` 的签名改为：

```csharp
Start(VpnChannel channel, DateTime connectBeganAt, ClashVpnPlugin owner,
      string fakeIpCidr, IList<string> nrptDns)
```

- 判据②的"系统解析器给出的答案必须落在假 IP 池里"改用 `DnsConfig.InCidr(fip, fakeIpCidr)`，
  证据句带 `pool=<生效 CIDR>`（旧实现硬写 `StartsWith("198.18.")`）。
- 隧道探针目标 = 本次实际下发的 NRPT DNS（只看 v4；
  `dnsInTunnel=0` 时弃权，与旧口径一致）。

### 5.5 `SubscriptionReload`：热重载重读

热重载路径与连接路径**同一套输入**：重新 `DnsConfig.Load()`、重新算 v6 池、
重新 `Transform`，日志附 `DNS 覆盖={dnsNote}` 与 `v6pool=`。
⇒ 内核侧改完 DNS 不必断开重连；NRPT 侧仍要断开再连（§7）。

### 5.6 前台：编辑器与证据

- `ClashUWP/Backend/DnsConfigStore.cs`（新）：
  - `LoadAsync()`：异步读文件；文件不存在/为空时显示 `ToText()` 模板；

  - `LastSnapshotAsync()`：从 `dataface-plugin.txt` 取 `Dns=` 行。
- `MainComponent` 的「设置」页新增 **「DNS 覆盖」** 区块（在「应用分流」与「诊断」之间）：
  多行原文编辑器（20000 字符上限）、「保存并校验」「重新读取」、
  当前文本摘要、**上次连接实际覆盖**、支持键清单、级联与生效时机说明、
  `fake-ip-range6` 需 `ipv6=2` 与 `dnsConfig=0` 总闸说明。
- 挂载时读一次（文件是手工文件，不会自己变）；`SaveDnsAsync` 保存后同时刷新快照。

## 6. 级联：一个假 IP 池，三个读者

这是本功能最容易"看起来对、实际埋雷"的部分。`fake-ip-range` 一旦可配：

| 读者 | 旧实现 | 现在 |
|---|---|---|
| 内核 YAML `dns.fake-ip-range` | 订阅原文 | `DnsConfig.FakeIpRange` 覆盖 |
| 窄 include 路由 | 常量 `198.18.0.0/16` | `DnsConfig.FakeIpRoute` |
| 看门狗判据② | `StartsWith("198.18.")` | `DnsConfig.InCidr(ip, 生效 CIDR)` |

只改第一处 = **域名流量不进隧道**（比黑洞更糟：以为在代理、其实直连）；
只改前两处 = **好隧道被看门狗判死**后自动拆线。三处必须一起走。

v6 池同一条纪律：`dns-config.txt: fake-ip-range6` > `settings.txt: ipv6FakeRange`
> 默认 `fdfe:dcba:9876::/64`，**只有 `ipv6=2` 时生效**。生效值同时用于：

1. `dns.fake-ip-range6`（内核）；★【1.0.129】**订阅自带的 `fake-ip-range6` 不再是第二个来源**：
   与生效池不同（含非 ULA）就被改写成生效池，并进 `DNS 覆盖=` 日志；
2. `tun.inet6-address`（池网络号 +1、`/126`）；
3. `Ipv6InclusionRoutes`（假 v6 池本身必须 include 进隧道）。

窄 include 里的 DNS `/32` 也换成**生效的 NRPT DNS**（`nrpt-dns` 覆盖后），
否则改了 DNS 服务器、到它的路由却还指着旧地址。

## 7. 生效时机

| 面 | 生效方式 | 说明 |
|---|---|---|
| 内核 `dns:` 块 | **断开再连** 或 **热重载** | 两条路都重新读文件、重新 `Transform` |
| NRPT（`nrpt-dns`） | **断开再连** | 插件在每次 Connect 的 `BuildDomainNames()` 里构造 `VpnDomainNameAssignment`，随 `StartWithTrafficFilter` 的 `namespaceScope` 交给平台；**不需要重建 profile**。此前"只有重建 profile 才改写"的说法把 `_config.DnsServers` 的来源与 NRPT 的下发路径混成了一件事，已按代码路径更正 |
| 总闸 `dnsConfig=0` | 下一次连接/热重载 | 文件不再读；内核覆盖与 NRPT 覆盖一起消失 |

★ `nrpt-dns` 还需 `settings.txt: dnsInTunnel=1` 才有意义 —— 为 0 时
`BuildDomainNames` 根本不会被调用（DNS 留物理网卡）。

## 8. 明确不做的（写明白，不当成 bug 猜）

1. **不开放任意 YAML。** 只支持白名单 14 个键；名单外的键拒绝并给原因。
2. **不额外新建第二份 `dns:` 块。** 订阅本身没有 DNS 配置时，先由 `EnsureDnsBlock`
   补一个最小基线块（档 0 的形态与 1.0.69 一致），覆盖再叠上去；
   `ApplyDnsOverrides` 的"没有 dns 块"只是防御分支。
3. **行内 `dns: {…}` 不改。** YAML 安全取舍（同 G6/G7）。
4. **块序列/块映射的父键不改。** 例如 `nameserver:` 换行跟 `- 1.1.1.1`：
   跳过并记 note，不留下"父键没了、子项还在"的孤儿行。
5. **`redir-host` 拒绝。** 与本项目的假 IP 路由/看门狗判据不兼容。
6. **`ts:` / `et:` / `dhcp:` 拒绝。** 要求目标 profile 存在，等组名校验。
7. **列表类键整条替换，不合并。** 想保留订阅默认就把原值抄回来。
8. **`nrpt-dns` 只下发，不建 v6 路由。** 它接受 v4/v6 字面量，但：
   窄 include 只对 v4 加 `/32`，看门狗隧道探针也只取 v4。
   v6 DNS 的可达性依赖 G7 的 `2000::/3`（全局 v6 DNS）；**ULA v6 DNS 不在路由里**——
   这是已知限制，不是"应该已经支持"。
9. **`fakeIp=0` 时整份改写关闭。** `KernelConfig.Transform` 压根不进，
   DNS 覆盖（含 `nrpt-dns` 之外的 YAML 项）不会应用；`nrpt-dns` 是独立路径，
   仍会进 NRPT。快照里 `Dns=fakeIp=0 → …` 可分辨。
10. **不改 Go、不重编 `clash_bridge.dll`。** 桥只吃生成后的 YAML。
11. **没有每键独立控件。** 编辑的是原文，校验在前台/插件两侧同一份解析器里做。
12. **`dns-config: ipv6=1` 在 `settings.txt: ipv6=0` 时仍会生效。** 它只改内核
    `dns.ipv6`（答不答 AAAA），不改隧道 v6 地址/路由。档 0 没有 v6 路由，
    重新打开 AAAA 等于把 G7 档 1 封掉的泄漏口又开回来 —— 想开 v6 请用 G7 的档位；
    DNS 侧的这个键只作为排障/单变量臂。档 ≥1 时该键被跳过（归属权在 settings）。

## 9. 上机验收清单

前置：装 1.0.71 包；`settings.txt` 保持默认（`dnsConfig=1`）。每一步只看
`LocalState\dataface-plugin.txt`、`logs/app.log`、`logs/plugin.log` 与系统命令，
**不要靠"感觉能上网"**。

1. **模板与保存**：设置页「DNS 覆盖」应显示模板（文件不存在时）；写一行
   `nameserver = 223.5.5.5` 点「保存并校验」→ 提示"已存 1 项"；刷新页面后正文还在。
2. **非法值被挡**：写 `nameserver = 1.1.1.1/33` 或 `enhanced-mode = redir-host`
   → 保存结果逐条给出原因；重新连接**必须仍然成功**（非法行没有进 YAML）。
3. **内核覆盖生效**：写 `fake-ip-range = 198.19.0.1/16` → 断开再连 →
   - 快照 `Dns=应用 N 项…`；
   - `Resolve-DnsName <域名>` 的答案落在 `198.19.x.x`；
   - 窄 include 的路由里出现 `198.19.0.0/16`（`Get-NetRoute`）；
   - 看门狗日志 `fake-ip=OK … pool=198.19.0.0/16`，**不能**出现 `NO`。
4. **NRPT 覆盖**：写 `nrpt-dns = 223.5.5.5`、确认 `dnsInTunnel=1` → 断开再连 →
   `Get-DnsClientNrptPolicy` 里该策略的 DNS 是 `223.5.5.5`（不是 profile 的旧清单）；
   快照 `DnsIntoTunnel=1 (223.5.5.5) nrpt=dns-config 覆盖`。
5. **热重载**：改内核侧键（如 `fake-ip-filter`）→「订阅 → 重新加载配置」→
   `channel=config` 日志出现新的 `DNS 覆盖=…`，**不断线**；
   改 `nrpt-dns` 后热重载 → 快照/NRPT 仍是旧值，断开再连才换（§7）。
6. **总闸**：`settings.txt: dnsConfig=0` → 重连 → `channel=settings` 有
   `dnsConfig=0`，`channel=dns` 明说总闸关闭，配置与 1.0.70 逐字一致。
7. **v6 池联动**（需要先按 Docs/22 开 `ipv6=2`）：
   `dns-config.txt: fake-ip-range6 = fdfe:dcba:9876::/64` → 快照 `v6pool=` 与
   `tun.inet6-address` 同源；改一个合法 ULA 前缀后重连，三处一起变。
8. **退出收尾**：断开后 `Get-DnsClientNrptPolicy` 不应残留根 Namespace 的规则、
   幽灵路由为 0（memory「Orphan NRPT machine blackout」的收工判据）；
   本批附带的恢复脚本见 Docs/24。

## 10. 未验证项（不写成已完成）

1. **整机零验证**：内核是否真吃到覆盖、NRPT 是否真的换掉、假池级联后域名流量
   是否仍进隧道 —— 全部需要一次真实连接。
2. **DoH/DoT 的实际可用性**未测：校验只保证 scheme 在内核白名单里，
   网络能否到达、证书是否可验不在本功能范围内。
3. **`fake-ip-filter` 的写法兼容性**：支持逗号分隔的域名/通配写法，
   但订阅里可能使用正则或 `geosite:` 一类扩展；这些值原样写入，
   内核接受与否只能上机看 `channel=dns`/内核日志。
4. **块写法父键**（`nameserver:` + `- …`）一律跳过，未在真实订阅上验证
   "跳过它到底影响多少"；note 会明说跳过了哪个键。
5. **`nrpt-dns` 的 v6 值**：代码允许纯 v6 字面量并构造 `HostName`，
   但窄 include 只加 v4 `/32`、看门狗只探 v4（§8.8），未上机验证。
6. **`dnsConfig=0` 的回退**只验证了代码路径与日志断言，未在装包后实测。
7. **热重载后的 REST 控制器**是否完整吃到新 `dns` 块（尤其 `fake-ip-range`），
   依赖桥的 reload 路径；本批没有新增桥侧代码，沿用既有热重载通道。
