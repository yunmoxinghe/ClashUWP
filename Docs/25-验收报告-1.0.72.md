## 一、本批修复内容

### 1.1 订阅 ↔ 系统 profile 同步（5 个互相放大的 bug）

| # | 问题 | 表现 | 修复 |
|---|------|------|------|
| 1 | 已存在 profile 走 Add | 每次 `注册=Other`，CustomConfiguration 永不更新 | 找到同 subId → 内容一致返回 Unchanged，不一致且 Disconnected 则 Update |
| 2 | 3 秒轮询回填 | app 内切订阅 B，3 秒后被撤销回 A | 边沿触发：只在 connectedSub **变化**时处理 |
| 3 | 重复 OnLaunched 泄漏 | 多点几次图标，多套组件 + 多条轮询 | Window.Current.Content 已有则跳过外壳构建 |

| 5 | 启动对账只补缺 | profile 漂移后永不修正 | 全量幂等对账：每份都调 Ensure，计数落一行 |

### 1.2 订阅显示名丢失（第 6 个问题）

**现象**：订阅响应头里有 `Profile-Title: 星链机场` 或 `Content-Disposition: filename*=UTF-8''%E6%98%9F%E9%93%BE%E6%9C%BA%E5%9C%BA.yaml`，但 UI 和系统 profile 只显示 URL 衍生的拉丁串（如 `iz9ld…-link-…`）。

**根因**：`FetchAsync` 忽略响应头，直接用 `MakeId(url)` 当名字。

**修复**：
- 新增 [`SubscriptionName.cs`](../ClashUWP/Backend/SubscriptionName.cs)：解析 Profile-Title / Content-Disposition，支持 base64、RFC 5987 UTF-8 百分号编码
- `FetchAsync` 读头 → 持久化 `subName:{id}=...` → UI 和系统 profile 优先用此名
- 同名冲突：UI 补 host，系统 profile 退回 host/id

### 1.3 AppListEntry 打包验证失败

**现象**：Plugin Application 缺 `Executable` / `EntryPoint`，MakeAppx 报 `error 80080204`。

**修复**：补上 `Executable="$targetnametoken$.exe"` 和 `EntryPoint="ClashUWP.Vpn.VpnBackgroundTask"`，同时移除 `AppListEntry="none"`（无头应用豁免需 Partner Center 申请）。

## 五、已知遗留问题

1. **`MakeId` 带 token**：订阅路径里的 token 会出现在文件名/profile 名/日志里。换 id 需迁移，不在本批范围。
2. **`MakeId` 忽略 query**：同 host + 同 path、仅 query 不同的两份订阅会撞 id。同上。
3. **老订阅不会自动获得新名字**：升级后要再点一次「更新当前订阅」才会把响应头名字补进 settings.txt。
4. **`SubscriptionView.LoadAsync` 的 mtime 取 `DateTime.Now`**：列表时间戳不是文件真实修改时间（只影响显示）。
5. **app 内切订阅 + 活动连接**：仍是"热重载配置、profile 仍指旧订阅"的形态。这是 Verge 式原地切换的代价。
