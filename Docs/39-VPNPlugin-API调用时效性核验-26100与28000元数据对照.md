# 39 · VPN Plugin API 调用时效性核验（26100/28000 元数据 + Learn 对照）

核验对象：仓库 HEAD（`Package.appxmanifest` Version=1.0.88.0）里所有对 `Windows.Networking.Vpn` 的**实际调用**（非注释）。
核验日期：2026-10-21。核验人：Qoder（本机实测元数据，未凭记忆）。

## 一、结论

**代码侧没有过时调用。**逐条比对结果：我们调的每一个 VPN plugin API，在当前 SDK（10.0.26100）与最新 SDK（10.0.28000）的 winmd 里都**没有 `Deprecated` 标记**，且官方 Learn 页面没有出现"may be altered or unavailable in the future / Instead, use X"这类废弃句式；而官方元数据里真正带废弃句式的四个类型（`VpnNamespaceAssignment`、`VpnNamespaceInfo`、`VpnDataPathType`、`IVpnCustomPrompt`）**我们一处都没用**（详见 §四）。

反向的问题倒是有一个，而且比"过时"更值钱：**产品默认的 send/receive 队列 API（`AppendVpnSendPacketBuffer` / `FlushVpnSendPacketBuffers`）官方要求 10.0.20348.0 起，而 `csproj` 声明 `TargetPlatformMinVersion=10.0.17763.0`，全仓又没有任何 `ApiInformation` 门控**（§五）。

另有两处**文档层面**的过时表述需要订正（代码无关，但会误导后来人）：§六。

```bash
  | grep -oE "channel\.[A-Za-z_]+" | sort -u

# 2) 元数据侧：ilspycmd 直接读 SDK 的联合元数据（不是凭记忆、不是凭旧文档）

#    VpnChannel 的 IVpnChannel5/6 成员在投影里是空的 ⇒ 必须以 Learn 的

D="$HOME/.nuget/packages/microsoft.windows.sdk.net.ref/10.0.26100.57/lib/net8.0/Microsoft.Windows.SDK.NET.dll"
ilspycmd -t Windows.Networking.Vpn.VpnChannel "$D"
```

## 四、明确"不在代码里"的旧形态（负面清单）

这些是官方元数据仍带着、但已被取代或本就不该用的形态。逐条 `grep`（剥注释后）命中数 **0**：

- `channel.Start(...)` —— 唯一入参类型是**已废弃**的 `VpnNamespaceAssignment`；1.0.16 起换 `StartWithTrafficFilter`（`trafficFilter=null` 那条先遣实测）。
- `channel.RequestVpnPacketBuffer(VpnDataPathType, out …)` —— `VpnDataPathType` 官方描述整句是废弃句式；1.0.52 删 `injectGetBuffer`/`sendGetBuffer` 两开关后统一走 `Get*PacketBuffer`。
- `new VpnNamespaceAssignment()` / `VpnNamespaceInfo` —— 官方明写 "Instead, use VpnDomainNameAssignment / VpnDomainNameInfo"。
- `channel.RequestCustomPrompt(IReadOnlyList<IVpnCustomPrompt>)` —— 旧式提示控件族（`VpnCustomCheckBox/ComboBox/EditBox/ErrorBox/TextBox`、`IVpnCustomPrompt`）整体废弃，替代是 `RequestCustomPromptAsync(IVpnCustomPromptElement)`；两者我们都没用。
- `channel.RequestCredentials(...)` → 返回 `VpnPickedCredential`（旧式凭据类型，替代 `RequestCredentialsAsync` → `VpnCredential`）；没用。
- `channel.SetAllowedSslTlsVersions(obj, bool useTls12)` —— 没用。
- `VpnManagementAgent.AddProfileFromXmlAsync` / `UpdateProfileFromXmlAsync` —— XML 那条路没用，全程 object API。
- `channel.NotifyStatus(...)` —— **元数据里从来不存在这个方法**（26100 与 28000 的成员表逐字一致，`grep -c Deprecated` = 0；本仓 1.0.75 已撤销该结论）。现在只在 `ClashVpnPlugin.cs:2267` 的注释里作为"当初为什么没编译过"的历史记录存在，不是调用。
- `IVpnChannel4` 一族（`AddAndAssociateTransport` / `ReplaceAndAssociateTransport` / `StartReconnectingTransport` / `GetSlotTypeForTransportContext` / `CurrentRequestTransportContext`，17134）与 `ActivateForeground`（`IVpnChannel6`，22000）—— 均未使用，属"尚未采纳的新 API"，不是过时项。

## 五、真正的风险（方向相反：不是太旧，是太新却没有门控）

| 项 | 事实 | 影响 |
| --- | --- | --- |
| `ClashUWP.csproj:5` | `TargetPlatformMinVersion=10.0.17763.0` | 声明支持 Win10 1803 起 |
| Learn: `AppendVpnSendPacketBuffer` | Device family "Windows 10, version 2104 (introduced in 10.0.20348.0)"，contract v12.0 | 17763/18362/19041 上此接口不存在 |
| 全仓 `grep ApiInformation / IsMethodPresent` | **0 命中**（`ClashVpnPlugin.cs` 亦为 0） | 无任何运行时探测或降级臂 |
| 产品默认 | 档 2（Append+Flush，每包 Flush）是 send 路径唯一实现 | 低于 20348 的机器上，出站数据面直接不可用（不是"性能差"，是 `IVpnChannel5` QI 失败） |
| `Package.appxmanifest:59` | `MinVersion="10.0.0.0"` | 商店元数据同样不会拦住低版本安装 |

本机是 26100，所以这一切**从未暴露**。上架前要么把 min 提到 10.0.20348.0（并同步 manifest），要么补 `ApiInformation.IsMethodPresent` 门控 + 出参 `encapulatedPackets.Append` 的官方契约降级臂。**此项未经真机验证**（没有 20348 以下的样本机器）。

## 六、需要订正的文档结论（两处）

1. `Docs/02-VPN连接失败根因与修复.md:85` —— "`Start` 的 `namespaceScope` 参数类型本就是 `VpnNamespaceAssignment`（**非废弃**）"。现读 Learn 的 `VpnNamespaceAssignment` 页面，整句摘要就是废弃句式（"is not supported and may be altered or unavailable in the future. Instead, use VpnDomainNameAssignment."），构造函数与 `NamespaceList`/`ProxyAutoConfigUri` 三条都标 "Not supported."。该结论当时成立与否不影响现在：**`Start` 这条路我们已经不用了**，但这句话留着会把后来人引回废弃类型。
2. `Docs/reference/VpnPlugin.annotated.cs`（阅读骨架）与 `Docs/01:393,421` —— 把 `channel.Start(...)` + `VpnNamespaceAssignment` + `RequestVpnPacketBuffer` 当"官方契约"教学。这三样恰好是官方现标注废弃/占位的组合。骨架本身照的是 sample 源码，历史价值保留即可，但要在文件头加一行"⚠️ 本骨架里的 `Start`/`VpnNamespaceAssignment`/`RequestVpnPacketBuffer` 已被 Learn 标注为旧形态，仓内实际走的是 `StartWithTrafficFilter`/`VpnDomainNameAssignment`/`Get*PacketBuffer`"，否则它会被当成现行口径复制。

## 七、本次用到的判据口径（避免下次再踩）

Learn 页面上的 "Not supported." 有两种含义，必须分清：

- **成员描述位的 "Not supported."** 是 winrt-api 文档对"没有写描述的成员"的统一占位（例：`SetErrorMessage(String)` 参数说明、`VpnDataPathType.Send/Receive` 字段说明）。**这不等于废弃**，元数据里也没有 `Deprecated` 属性。
- **类型/方法摘要整句 "X is not supported and may be altered or unavailable in the future. Instead, use Y."** 才是真废弃标记（例：`VpnNamespaceAssignment`、`VpnDataPathType`、`VpnPickedCredential`、`IVpnCustomPrompt`）。

判"过时"要三头对齐：**winmd 有无 `Deprecated` 属性** + **Learn 摘要是否为废弃句式** + **投影/元数据的 `ContractVersion` 与 Learn 的 min build 是否一致**。只看其中一头会得出错结论（本次就是先看属性、再看句式、最后拿 Learn 表补 min build）。
