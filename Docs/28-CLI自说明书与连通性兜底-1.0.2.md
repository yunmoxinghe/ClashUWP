# 28 · CLI 自说明书化 + 连通性兜底（ClashUWP.Cli 1.0.1 → 1.0.2）

【这一版要解决的两件事，都是"人不在场时也能安全操作"】

1. **让别的 AI 不用学也会用**。1.0.1 的命令清单只活在 `Usage()` 的一行字符串里，和主应用
   `DebugCommandLoop` 的注释各说各话：不知道命令的人必须先读 app 源码才敢下发，下发错了要
   回 app 日志里才发现错 —— 一次来回。而且"哪条命令会碰隧道"这件事只写在注释里，等于
   靠自觉。现在它是一张表 + 一道闸。
2. **连通性兜底**。指定一个真正关心的目标（例如 google 的 204），连续探不通就自动
   `disconnect` 把网络还给物理网卡并退出。主应用侧的 HealthMonitor 探的是它自己写死的
   三个靶子（见 Docs/18 与 `HealthMonitor`），guard 补的是另一半：**由当下这个人/AI 指定目标**。

产物：`ClashUWP.Cli\ClashUWP.Cli_1.0.2.0_x64.msix`（签名 Valid，CN=gold，3.12 MB）。
打包配方与两条实测细节见 Docs/13 §5.2，本轮只把版本号从 1.0.1.0 推到 1.0.2.0。

## 1. 文件划分：Program 只做路由

| 文件 | 职责 | 为什么单独成文件 |
| --- | --- | --- |
| `Program.cs` | 解析全局开关 → 选路（元命令 / 透传）→ 汇总结果 | 业务细节一旦留在 Main 里，就会有两处决定"这条命令能不能发" |
| `CommandCatalog.cs` | **命令表 = 唯一数据源**：级别、参数、说明、别名、校验、help、JSON | help / json / 校验 / 危险闸门四处读它，加一条命令只改一处 |
| `AppServiceChannel.cs` | 连接、发送、超时、包发现、退出码表 | 命令透传 / guard 兜底 / doctor 体检共用一套，15s 连接超时这个实测结论不会漂 |
| `Probe.cs` | TCP / HTTP 探测原语 + 目标解析 | guard 反复问、doctor 问一次；两处各写一遍就会"guard 说通、doctor 说不通" |
| `Guard.cs` | 连通性兜底循环 | —— |
| `Doctor.cs` | 六阶段体检 | —— |
| `SelfTest.cs` | AOT/WinRT 投影自检（从旧 Program.cs 原样搬出） | 这四项是**运行时**才能验的，命令必须留着，别当一次性验证删掉 |

## 2. 危险分级是代码，不是注释

每条命令标三级：

- `read` —— 纯读，任何时候可发（status / groups / conf / controller / logs / logtail / sub / sublist / profiles）
- `state` —— 改内核运行态或落订阅文件，不碰隧道，但会改变"下一次连接走哪个节点"（delay / connections / select / mode / bind / reload / subfetch / subupdate / subuse / subdel）
- `tunnel` —— 拨号、拆隧道、改系统 VPN profile，失败形态是整机断网（connect / disconnect / recreate / probe）

闸门规则（`CommandCatalog.NeedsForce` + `Program.PassThroughAsync`）：

- `connect / recreate / probe` 必须带 `--force`，否则**本地就拦下**，返回退出码 7，命令根本不发出去。
- **`disconnect` 刻意不拦**：它是把网络还回去的逃生口，给逃生口加闸门 = 断网时的远程自救也做不了，
  那正是 Docs/08 §10.10 付过的学费。
- **表里没登记的名字一律按 `tunnel` 处理**（`LevelOf` 的 fail-closed）。这张表漏一条时，
  宁可多要一次 `--force`，也不能把"没见过"当成"安全"。实测：

```
$ clashuwp-cli foobar
注意：「foobar」不在本工具的命令表里 —— 可能是主应用版本比这张表新，也可能是拼错了。
  看已登记的命令：clashuwp-cli --commands --json
已被拦下：「foobar」级别 = tunnel，会拨号/拆隧道/改系统 VPN profile。
  这类命令的失败形态是整机断网，所以自动化必须显式确认：在命令前加 --force
  发之前先看现场：clashuwp-cli doctor
  例外：disconnect 不要求 --force —— 它是把网络还回去的逃生口。
exit=7
```

本地参数校验只挡三类零歧义笔误（枚举值写错 / 必填入参整体缺失 / URL 明显不是 URL），
**刻意不做厚**：真身是主应用的 `ExecuteAsync`，在这边再抄一套等价语义，两份迟早漂，
漂了之后 CLI 会拦掉一条本来合法的命令 —— 那比不校验更糟。

命令数核对：本地表 23 条（read 9 / state 10 / tunnel 4），与服务端 `DebugCommandLoop` 的
case 数一致；`--commands --json` 回读 `需要force的: connect,recreate,probe`。

## 3. 三种读法，同一张表

```
clashuwp-cli                     # 整份说明书（无参数就给 help，而不是甩一句"缺少命令"）
clashuwp-cli --commands --json   # 机器可读：{tool, exitCodes, commands[{name,args,danger,needsForce,summary,aliases}]}
clashuwp-cli help connect        # 单条口径：级别 / 参数 / 要不要 --force / 可直接抄的下发行
```

help 正文的命令表每行固定 `级别 | 命令 | 参数 | 说明`，竖线在人眼里是列分隔，
在脚本里就是一次 `split` —— 人和机器同一份，不需要为了机器再写一遍。

JSON 是手写的（`JsonText()`）：本工程 Native AOT，反射式序列化要么裁剪告警要么运行时炸，
这张表本来就一维数组。**别改回 System.Text.Json**，csproj 注释里也记了这条。

退出码（`ExitCodes`，与 help 和 JSON 同源）：
`0` 成功 · `2` 连不上主应用 · `3` 服务端报错 · `4` 参数/包发现 · `5` 超时 ·
`6` selftest 失败 · `7` tunnel 未加 --force · `8` guard 触发且已拆 ·
`9` guard 触发但拆失败（隧道可能还在，要人工） · `10` guard 干跑（`--then none`）。

## 4. guard —— 连不上就自动退出

```
clashuwp-cli guard https://www.google.com/generate_204 --expect 204 --interval 10 --fail-max 3
clashuwp-cli guard 223.5.5.5:443 --then none          # 只报不拆（干跑）
```

四条设计决定，都是踩过坑之后定的：

1. **只拆不建**。兜底动作只有 `disconnect`，没有"失败就重拨"。RasMan 无条件重拨把用户网络
   占一整天（run 25 量到单日 dial=413）就是这条纪律的来源：要重连必须由人明确下达 `connect`。
2. **判连通不能看 DNS**。隧道用 fake-ip，域名**一定**解析得通，解析成功毫无信息量。
   所以默认走 tcp（或 http 看有没有回），`--expect` 只卡状态码不卡内容。
3. **`--duration` 默认 900s**。自动化的常态是"跑着跑着就忘了"，一个每 15 秒探一次的循环
   留下就是长期占机器；到点自己退出并返回 healthy，比无限期守着安全。要长跑自己写 `--duration 0`。
4. **拆失败要单独一个码**。判定不可达、但 `disconnect` 本身也没做成（主应用没在跑 / 通道不通）时，
   隧道可能还挂着 = 整机仍是黑的，而外部只知道"guard 退出了"。所以回退出码 9，
   并把手工出口原话给出来（`rasdial /disconnect`，或按 Docs/16 清残留 NRPT 与死接口路由）。

实测（本机零网络影响：打的是 `127.0.0.1:9` 这个关闭端口，且 `--then none` 不发包）：

```
[guard] 目标=tcp 127.0.0.1:9 方式=tcp 单次超时=2s 间隔=1s 连续失败阈值=1 总时长=10s 兜底动作=none
[guard] #1 01:15:48 ok=0 2005ms 连续失败=1/1 tcp 失败 127.0.0.1:9 超时
[guard] 判定：连续 1 次探不通 tcp 127.0.0.1:9（观察 2s）
[guard] VERDICT=unreachable --then none：未动隧道（干跑）。要自动拆就去掉 --then none
exit=10
```

`--port` 的优先级也在这轮修掉了旧坑：目标里写了端口 > `--port` > scheme 默认 > 443 兜底。
1.0.1 时代 `guard host --port 8443` 会被 scheme 的默认值吃掉、静默默认按 443 探测 ——
现在 `Target` 带 `PortGiven` 旗标，实测 `guard 127.0.0.1 --port 9` 打的就是 9。

## 5. doctor —— 一条命令回答"卡在哪一环"

```
clashuwp-cli doctor                    # 六阶段全跑（只发两条纯读命令）
clashuwp-cli doctor --offline          # 只做包发现，零 IPC
clashuwp-cli doctor --target https://www.google.com/generate_204 --expect 204
```

阶段固定：1 包发现 · 2 本工具的 WinRT/AOT 通路 · 3 AppService 通道 · 4 内核应答 ·
5 系统 VPN profile · 6 数据面连通（给了 `--target` 才跑）。每行都是
`阶段N · [PASS|FAIL|WARN|SKIP] · 结论 → 下一步：…`。

这轮在 doctor 上被抓到的两个判据错误，都值得单独记：

**(a) "命令返回 0"不等于"内核在跑"。** 服务端在失败时也是**正常回话**（回的是失败原因原文），
第一版用"回话里不含 refused/异常/不可达 就算通"判 —— 实测内核没跑时它回
`status 查询失败: HttpRequestException: 由于目标计算机积极拒绝 (127.0.0.1:9090)`，
字样一个没命中，于是把黑洞读成了绿灯。**现在按服务端 `RunStatusAsync` 的成功形状判**：
成功必然是 `mode=… | log-level=… | interface-name=…`，所以 `StartsWith("mode=")` 才算内核应答。
`profiles` 同理：有 profile ⇒ `共 N 条：…`，一条没有 ⇒ `本包名下没有任何 profile`。
（这和 Docs/13 §6.3、记忆里"三个会把绿读反的口径"是同一类错误：**判据要落在机器契约上，
不能落在文案情绪上**。）

**(b) 内核不应答本身不是故障，缺参照物才是。** 没连着的时候内核本来就不跑。
所以 doctor 把阶段 4 的 WARN 留到阶段 5 之后合判：会话里有 `状态=Connected` 却内核不应答
⇒ 记 issue；全都 Disconnected ⇒ 明说"这是空闲态，不算故障"，VERDICT 仍是 ok。

实测（当前机器 = 已装 1.0.72、未连接，正是空闲态）：

```
[doctor] 阶段1 · [PASS] · 已安装 v1.0.72.0 · PFN=421769c5-…_y0tg80em3rma2
[doctor] 阶段2 · [PASS] · PackageManager 包枚举可用（本进程 WinRT 通路通）
[doctor] 阶段3 · [PASS] · AppService 通道连通，主应用已应答
[doctor] 阶段4 · [WARN] · 内核未应答（REST 9090 拒连）：status 查询失败: … 积极拒绝 …
[doctor] 阶段5 · [PASS] · 共 4 条： | ClashUWP · iz9ld.no-mad-sub.one | … | 状态=Disconnected | …
[doctor] 说明：阶段4 的 WARN 是空闲态 —— 没有已连接会话时内核本来就不跑，这不算故障。
[doctor] VERDICT=ok —— 包、通道、profile 就位（当前空闲：没有已连接会话，内核未起）；未做数据面判定，加 --target 才做
exit=0
```

阶段 5 还会把服务端标的 `[探测残留]`（上一轮 probe 没收尾留下的临时 profile）判成 WARN
并给出清理路径，因为这种 profile 会出现在快速设置面板里。

**doctor 全程只发 read 级命令**（status / profiles），所以任何时候都能跑，包括正连着的时候。

## 6. 本轮验过什么、没验什么

已在本机 AOT 产物上实测（零网络影响：探测目标是 `127.0.0.1` 的关闭端口）：

| 项 | 结果 |
| --- | --- |
| `dotnet publish`（AOT，win-x64） | 通过，`clashuwp-cli.exe` 单文件 6.7 MB，0 错误 |
| `selftest`（ValueSet / 连接构造 / 包枚举 / OpenAsync 异步跨 ABI） | 4 项全 PASS，237 个包 |
| 无参数 → help 全表（23 条） | 正确 |
| `--commands --json` 合法性 | `ConvertFrom-Json` 解析通过：顶层键 tool/exitCodes/commands，23 条，needsForce=connect,recreate,probe |
| `help connect` 单条口径 | 正确 |
| `connect` 不带 --force | **本地拦下，命令未发出**，exit=7 |
| `mode bogus` 参数校验 | exit=4，回"只认 rule/global/direct"+ 指向 `help mode` |
| 未登记命令 `foobar` | fail-closed 成 tunnel，exit=7 |
| `list` / `doctor --offline` | 反查到 PFN 与已装版本 |
| `doctor` 全量（两条纯读透传） | 阶段 3 PASS，阶段 4 正确读成"内核未应答"，VERDICT 判成空闲态 ok |
| `doctor --target 127.0.0.1:9` | 阶段 6 FAIL → VERDICT=issues → exit=3（判据不再被文案骗） |
| `guard … --then none` | 干跑 exit=10，未动隧道 |
| `winapp package` | `ClashUWP.Cli_1.0.2.0_x64.msix`，签名 Valid，CN=gold |

**没验的三件事，别当成做了**：

1. **guard 真拆隧道那条分支**（`disconnect` 下发 + 回话判读）。按项目纪律，碰隧道的命令
   未经明确指定不下发；这台机器当前也没连着。代码路径与错误出口都写好了，
   等一次真连着的时候用 `guard <目标> --fail-max 1 --duration 60` 验一次即可。
2. **arm64 AOT 发布**没跑过（本机 x64）；多架构 `.msixbundle` 没打。同 Docs/13 §5.2。
3. **1.0.2.0 包在本机的安装与别名首测**没做 —— 部署走 Visual Studio 是项目规矩（AGENTS 第 2 条），
   且这台机器的 `Add-AppxPackage` 不可用（Docs/13 §6）。装之前先看部署队列状态（Docs/13 §6.1）。

## 7. 与上一版的行为差异（升级时要知道的）

- 新增：`doctor`、`guard`、`help <命令>`、`commands`（`--json`）、`version`。
- 变更：`connect / recreate / probe` 不再能裸发，必须 `--force`（退出码 7）。脚本里原来直接
  写 `clashuwp-cli connect xxx` 的地方要改成 `clashuwp-cli --force connect xxx`。
- 不变：`--pfn` / `--timeout` / `list` / `selftest` 的语义，以及与服务端那张命令表的**逐字同义**
  —— 两条通道（AppService 与 `LocalState\debug-cmd.txt`）仍然一份命令表，见 Docs/13。
