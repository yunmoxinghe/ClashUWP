## 3. 现有数据流（修复后）

```
订阅 URL
  │  SubscriptionManager.FetchAsync(url, activate)
  │    ├─ HttpClient(UseProxy=true) 取正文 + 响应头取订阅名
  │    ├─ ★ M1 SubscriptionShape.ProbeShape(text)  落盘前校验（顶层键 + 拒 HTML）
  │    ├─ ★ M5 _fetchGate.WaitAsync()  串行化「落盘 + 激活 + 热重载」
  │    ├─ 写 subscriptions/{id}.yaml
  │    ├─ activate? → 复制为 config.yaml + SetActive + ReloadActiveConfigAsync
  │    │      └─ ★ M8 内核在线时：RunReloadAsync 真实成败据 IsReloadSuccess 判定；
  │    │         成功后再探活（IsKernelUpAsync）确认核心未崩 ⇒ 「核心已接受」判据
  │    └─ finally _fetchGate.Release()
  ▼
config.yaml（内核实际读取；Vpn 组件读它）
  │  Mihomo 内核（clash_bridge.dll）
  ▼
GET 127.0.0.1:9090/proxies
  │  MihomoController.ReadProxiesTable(root)
  │    ├─ 分类（all 数组判组 / 内置策略过滤 / 延迟取顶层 history）
  │    ├─ ★ M4 读 provider-name → ProxyInfo.ProviderName
  │    └─ ★ M3 IsSelectableGroupType 含 Selector/URLTest/Fallback/LoadBalance/Relay
  ▼
KernelView（UI 结构化视图）
  │  Group.IsUserSelectable：Selector / relay 可手选；URLTest/Fallback/LoadBalance 否（★ M3）
  │  Member.ProviderName：来自 provider 的节点显示来源副标题（★ M4）
  ▼
KernelView.LoadAsync ★ M7 额外 GET /providers/proxies → Snapshot.Providers
  │  解析 vehicleType / 已加载节点数 / updatedAt / subscriptionInfo（流量·到期）
  │  失败只作补充信息，不影响代理组/节点/连接
  ▼
MainComponent（WinUI 渲染）
  代理页「订阅源（提供方）」面板：类型/节点数/更新时间/流量到期 + 每行 healthcheck 刷新按钮
  订阅区块：★ M2 SubscriptionView.Parse 已识别 proxy-providers，纯提供方不再显示 0 节点
```

## 5. 修改清单（M1–M8 已落地；M7/M8 为可选增强，本轮一并补齐）

1. **M1（修 Q1/Q2）** 新增 `ClashUWP/Backend/SubscriptionShape.cs`（**纯函数、无 IO、无 WinRT 依赖**，可被离线夹具直测）。`SubscriptionManager.FetchAsync` 落盘前调用 `ProbeShape`：要求至少一个顶层键 `proxies:` / `proxy-providers:` / `proxy-groups:`，并拒绝 HTML 特征。失败不覆盖缓存。
2. **M2（修 Q3）** `SubscriptionView.Parse` 识别 `proxy-providers` 段（映射写法 `p1:` 与列表写法 `- name:` 都认），计 `ProviderCount` 与 `InlineProviderNodes`（inline 的 `payload:` 节点）；新增字段并传播到 `SubscriptionManager.Profile` 与列表/元信息展示，纯提供方订阅不再显示虚 0 节点。
3. **M3（修 Q6/Q7）** `relay`/`Relay` 纳入 `MihomoController.IsSelectableGroupType` 与 `KernelView.Group.IsUserSelectable`（与 `Selector` 同为手动组，选择持久）；`LoadBalance` 维持只读；自动组提示排除 `relay`。
4. **M4（修 Q8）** `MihomoController.ReadProxiesTable` 读 `provider-name` 进 `ProxyInfo.ProviderName`，流经 `KernelView.Member.ProviderName`，`MainComponent.MemberSubtitle` 对 provider 节点补「· 提供方名」来源副标题。
5. **M5（修 Q5）** `SubscriptionManager` 加 `SemaphoreSlim(1,1)` 串行化「落盘+激活+热重载」；`finally` 释放，所有返回路径不死锁。
6. **M6（修 Q9）** fetch 异常只记异常类型（不把 URL 写进用户文案/日志）；`OneLine` 生效 URL 只显示 host。
7. **M7（修 Q10）** 对接官方 `GET /providers/proxies` 端点：
   - `MihomoController` 新增 `ProviderInfo` record（Name/VehicleType/NodeCount/UpdatedAt/SubUpload/SubDownload/SubTotal/SubExpire）、纯函数 `ReadProvidersTable(JsonElement)`（解析 `providers` 对象；缺字段不抛、缺 name 用对象 key 兜底）、`GetProvidersAsync`（GET /providers/proxies，失败返回空列表）、`TriggerProviderHealthCheckAsync`（GET /providers/proxies/{name}/healthcheck，204=已触发刷新）。
   - `KernelView.Snapshot` 增 `Providers` 字段；`LoadAsync` 加第④步独立 try 调 `GetProvidersAsync`（失败只留空、不写全局 error）。
   - `MainComponent` 代理页新增「订阅源（提供方）」面板（`ProviderPanel`）：展示每提供方类型/已加载节点数/最近更新/订阅流量与到期（仅 http 订阅），每行「刷新」按钮触发 healthcheck 后重载快照（`RefreshProviderAsync`）。
8. **M8（修 Q12）** 闭合「下载成功但核心加载失败」窗口：
   - 新增 `MihomoController.IsReloadSuccess(string)`（**纯函数、可离线直测**）：只认 `RunReloadAsync` 返回的「`重载成功`」前缀，非 2xx / 异常 / 缺参数一律判失败。
   - `SubscriptionManager.ReloadActiveConfigAsync`：内核在线时不再硬编码 `Result(true)` —— 据 `IsReloadSuccess` 把内核拒收判为失败；成功后追加「核心接受度判据」：再次 `IsKernelUpAsync` 探活，无应答即判「新配置可能把核心搞崩」并返回失败，返回文案带「（核心已接受并在线）」。
   - `FetchAsync`（拉取并启用）与 `ActivateAsync`（切订阅）均改为传播 `reload.Ok`，内核拒收/崩溃时整体标失败，不再报「已拉取/已切」假成功；内核未连接时仍返回明确的「下次连接自动加载」提示（不伪装成失败）。
9. **M9（修 Q11）** `MihomoController.ReadProxiesTable` 改为返回 `Duplicates` 计数：扁平 `ByName` 字典一旦遇到同名条目会静默覆盖，`duplicates` 把"覆盖"这个动作**记下来**而非默默发生；`RunGroupsAsync`（debug 诊断）在 `duplicates>0` 时明确提示"内核返回了 N 处同名条目，已按名字折叠，切换以组作用域仍正确、但展示层可能错位"。成员分类（嵌套组 / 真节点 / 内置策略）在组作用域内稳定、互不误标，离线新增 `NameCollision` 用例钉死（良构响应 `Duplicates=0`、嵌套组与真节点/策略各自标对、`RealNodeCount` 不计嵌套组）。
10. **M10（修 Q13）** `SubscriptionView.Parse` 在**全局命名空间**（节点名 + 组名 + 内置策略保留名 `DIRECT/REJECT/GLOBAL…`）检测重名：mihomo 的代理名/组名/内置策略共享同一扁平命名空间，重名会被内核折叠或报错且行为未定义——这是唯一能观察重名的地方。`Info` 新增 `DuplicateNames`，`OneLine` 元信息摘要直接告警（`⚠ 重名检测: …`）。离线新增 `DuplicateNames` 用例钉死（同名节点 / 节点名==组名 / 撞保留名 均检出；干净订阅为空）。

> M7/M8 原为可选增强，本轮一并补齐；M9/M10 为 Q11/Q13（P3 边缘项）的收尾，至此 **Q1–Q13 全部修复或缓解**，审计清单闭环。

**新增 Q4 修复（客户端侧选择持久化，非 M1–M8 之列）**：
- 新增 `ClashUWP/Backend/SelectionStore.cs`：纯客户端持久化层。`Record(group,node)` 把每次手动组选择写入 `LocalState/selection.txt`（每行 `UrlEncode(组)=UrlEncode(节点)`，用 UrlEncode 防止组名/节点名里的 `=`/空格/中文破坏按首个 `=` 切分）；`LoadAll`/`Forget` 配套。`SelectionStore` 与 `SubscriptionManager`/`MihomoController` 无耦合，可被离线夹具直测其编解码。

- `MainComponent` 轮询：成功 `LoadAsync` 后触发回放（`selection-replay` 入日志），`catch` 中复位边沿。

## 7. 遗留风险

- **R1（M8/Q12）**：**已修复**。重载后核心接受度判据已闭合——内核拒收/崩溃不再被伪装成「已拉取/已切」成功；内核未连接时仍按既有明确提示处理。
- **R2（relay 可手选的官方确认）**：`relay` 组的 `PUT` 选节点依赖「通用选择接口类型无关」的推断 + 与 `Selector` 同为用户决策组的代码一致性；官方 API 文档未在策略组示例列出 `Relay`。**建议真机实测确认**。即便该推断偏差，也只影响 relay 组是否被允许点选，不影响其余 5 项修复。
