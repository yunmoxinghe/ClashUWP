## 二、★ 真根因：`Upload\AppxManifest.xml` 不随构建刷新

### 2.1 症状（服务端一手回显，不是我读出来的）

Partner Center 的"包"页把每个上传包的**内层身份版本**单独列了一行，两条都对不上文件名：

```
ClashUWP_1.0.91.0_x64.msixupload   v1.0.88.0, X64
ClashUWP_1.0.81.0_x64.msixupload   v1.0.77.0, X64
```

也就是说这个坑不是一次事故，**至少从 1.0.77 起每一版都在咬**（`Upload\` 目录下攒着 `ClashUWP_1.0.76.0_x64` 一直到 `1.0.91.0_x64` 的子目录，每一版的上传包都带着同一份陈旧清单）。

### 2.2 取证：同一次构建产出的三个包，身份版本不一样

`clashuwp-build-1091.log`（01:34，`ok:True`，135 s）一次构建同时产出侧发包和上传包，日志里两条 `PackageSuccessfullyCreated` 都有。逐个开包读 `AppxManifest.xml` 的 `<Identity>`：

| 产物 | 内层 Identity Version | 判定 |
| --- | --- | --- |
| `AppPackages\ClashUWP_1.0.91.0_x64_Test\ClashUWP_1.0.91.0_x64.msix`（侧发、已装机那份） | `1.0.91.0` | ✅ |
| `bin\…\win-x64\Upload\ClashUWP_1.0.91.0_x64\ClashUWP_1.0.91.0_x64.msix`（上传暂存） | `1.0.88.0` | ❌ |
| `AppPackages\ClashUWP_1.0.91.0_x64.msixupload` 里那层 `.msix` | `1.0.88.0` | ❌ |

两份清单文件本身：

```
14580 B  10-22 01:34   win-x64\AppxManifest.xml            → Version="1.0.91.0"
14580 B  10-22 00:06   win-x64\Upload\AppxManifest.xml     → Version="1.0.88.0"
```

字节数完全相同，只差版本号 —— 排除了"代码回退"这类解释；差异纯粹是**清单来源不同**：侧发路径用现生成的 `win-x64\AppxManifest.xml`，上传路径用 `Upload\` 里那份**上次留下的**清单。

### 2.3 机制（推断，未逐行读 msbuild 目标）

`Upload\AppxManifest.xml` 只在"上传暂存"第一次建立时写入，之后构建只往 `Upload\ClashUWP_<版本>_x64\` 里追加新子目录、打包，却**不刷新那份清单**。所以版本号被永久钉在暂存目录第一次被创建的那一版（本机是 1.0.88.0，对应 00:06 那次构建）。

这一条我只证到"删掉它就会重新生成为当前版本"，没有去核对到底是哪个 target 上的 `!Exists(...)` 条件在跳过它。**别把 2.3 当结论用，用 2.4 的判据。**

### 2.4 修复与复验（全程走 VS 桥，合规 AGENTS.md 第 2 条）

```
1) 把陈旧清单挪走（留了备份，没删）：
   win-x64\Upload\AppxManifest.xml
     → win-x64\Upload\AppxManifest.xml.stale-1.0.88.bak

2) 重建上传包：
   Tools\UwpBridge\uwp-bridge.exe
     -build D:/fluentapps/repos/ClashUWP/ClashUWP/ClashUWP.csproj
     -configuration Release -platform x64 -target Publish
   → ok:True  exitCode:0  112 s  PackageSuccessfullyCreated

3) 复验（开包读 <Identity>）：
   Upload\AppxManifest.xml                                  → 03:43, Version="1.0.91.0"  ✅ 重新生成了
   Upload\ClashUWP_1.0.91.0_x64\…msix  内层 Identity         → 1.0.91.0  ✅
   AppPackages\…_Test\ClashUWP_1.0.91.0_x64.msix 内层 Identity → 1.0.91.0  ✅
   AppPackages\ClashUWP_1.0.91.0_x64.msixupload 内层 Identity  → 1.0.91.0  ✅（51,714,740 B）
```

### 2.5 ★ 上传前的硬判据（以后每版必查，别信文件名）

文件名里的版本只是 VS 拼字符串，**包内身份才是 Store 看到的版本**。收工判据一条：

> 打开 `.msixupload` → 取出里面那层 `.msix` → 读 `AppxManifest.xml` 的 `<Identity … Version="…"/>`，
> 它必须**逐字等于**文件名里的版本；不等就是撞上了 §2.2，按 §2.4 修。

（本轮用的读法在 §2.4 的复验里；`pwsh` 7 + `System.IO.Compression.ZipFile`，注意 `.msixupload` 是**两层** zip，第一层里没有 `AppxManifest.xml`。）

## 七、这轮踩到的 UIA 小坑（记下来省下次的时间）

- `winapp ui` 的每条命令都要重新带 `-w <HWND>`，不带就报 "Target app required"；上一轮那些"成功"的裸命令其实是打在别的窗口上的。
- 单选钮的真实状态只能靠 `get-property <slug>` 的 `IsSelected`，**别拿截图当判据** —— 页面横向溢出时截图会把问题文本裁成半截（本轮 `ar-04.png` 就是这样，看着像没答，其实 12 项全在）。
- "保存/提交"之后页面会跳回"应用程序概述"，此时旧 slug 全部失效，且**同一个名字可能同时匹配多个元素**（`invoke "主页"` 会打到 Edge 的工具栏主页按钮，直接把浏览器导航走）。导航一律用左侧 `leftnav-*` 或状态链接（`lnk-… "包 状态: - 完成"`）。
- 原生"打开"文件框：`set-value` 写 `txt-1148-…` 那个"文件名(N):"编辑框，再 Invoke `Button "打开(O)"`，比在文件列表里翻路径稳。
- 中文长文本进网页输入框：`Get-Content -Raw -Encoding UTF8 file | Set-Clipboard`（5.1 的 `Set-Clipboard` 没有 `-Raw`，参数是 `-Value`），然后 `focus <slug>` + `send-keys "ctrl+v" --via send-input`。
