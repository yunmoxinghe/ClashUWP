# 34 · 状态通知优化：点击打开主窗口 + 断开连接按钮（应用 1.0.81）

## 0. 用户诉求

原话："优化通知，需要点击后正确打开主窗口，并且点击后通知不会消失；添加断开链接按钮；只要断开链接后才关闭通知，否则应实时显示网速"

## 1. 落地形态

| 功能点 | 实现方式 | 官方依据 |
| --- | --- | --- |
| **点击通知主体打开主窗口** | Toast XML 加 `launch='action=viewMainWindow'`，App.OnActivated 识别后调 `Window.Activate()` | [Toast schema](https://learn.microsoft.com/zh-cn/windows/apps/develop/notifications/app-notifications/toast-schema)：`launch` 属性定义点击主体的激活参数 |
| **点击后通知不消失** | 通知主体用 `SuppressPopup=true`（静默通知），点击只触发前台激活但不 dismiss 通知 | [App notification content](https://learn.microsoft.com/en-us/windows/apps/develop/notifications/app-notifications/adaptive-interactive-toasts)：静默通知点击后默认留在通知中心 |
| **"断开连接"按钮** | `<actions>` 里加一个 `activationType='foreground'` + `hintAfterActivationBehavior='pendingUpdate'` 的按钮 | [Toast schema](https://learn.microsoft.com/zh-cn/windows/apps/develop/notifications/app-notifications/toast-schema)：`hintAfterActivationBehavior='pendingUpdate'` 让通知保持"待更新"状态而不消失 |
| **点击按钮后断开连接** | App.OnActivated 收到 `action=disconnect` 后调 `VpnSession.DisconnectAsync()`，成功后 `StatusToast.Stop()` 会 Hide 掉通知 | 现有 Disconnect 链路不变，只是多了一个入口 |
| **实时更新网速** | 循环继续每秒读计数、变了才 Update，与之前逻辑完全一致 | 无变更 |

### 2.3 StatusToast.cs（插件进程内）

**XML 模板新增 actions 与 launch 参数：**

```xml
<toast launch='action=viewMainWindow'>
  <visual>
    <binding template='ToastGeneric'>
      <text>{statusTitle}</text>
      <text>{statusRate}</text>
      <text>{statusTotal}</text>
    </binding>
  </visual>
  <actions>
    <action content='断开连接' activationType='foreground' 
            arguments='action=disconnect' 
            hintAfterActivationBehavior='pendingUpdate'/>
  </actions>
  <audio silent='true'/>
</toast>
```

关键点：
- `launch='action=viewMainWindow'`：点击通知主体时的激活参数
- `activationType='foreground'`：按钮点击触发前台激活（App.OnActivated 会被调用）
- `hintAfterActivationBehavior='pendingUpdate'`：点击后通知进入"待更新"状态（显示加载指示器），不会自动消失

**Start 方法改用显示名:**

```csharp
// ★【1.0.81】优先用显示名（如"星链机场"），没有则回退到 subId
string profile = config.SubDisplayName.Length > 0 ? config.SubDisplayName
              : config.SubId.Length > 0 ? config.SubId
              : "默认配置";

_title = $"ClashUWP · 隧道运行中（{profile}）";
```

### 2.4 App.cs（前台 UWP 进程）

**OnActivated 新增 Toast 激活分支：**

```csharp
protected override void OnActivated(IActivatedEventArgs args)
{
    // ★【1.0.81】先检查是不是 Toast 激活
    if (args is Windows.ApplicationModel.Activation.ToastNotificationActivatedEventArgs toastArgs)
    {
        string arguments = toastArgs.Argument ?? "";
        
        if (arguments.Contains("action=viewMainWindow"))
        {
            // 点击通知主体：打开/激活主窗口
            ActivateMainWindow();
            return;
        }
        
        if (arguments.Contains("action=disconnect"))
        {
            // 点击"断开连接"按钮：触发断开逻辑
            TriggerDisconnectFromToast();
            return;
        }
        
        return;
    }
    
    HandleActivation(args);  // 原有的协议激活处理
}
```

**新增两个辅助方法（含冷启动修复）：**

```csharp
/// <summary>把主窗口带到前台；如果窗口为空则重建 Reactor 外壳</summary>
private static void ActivateMainWindow()
{
    var window = Windows.UI.Xaml.Window.Current;
    
    // 窗口不存在或内容为空：需要重建 Reactor 外壳（冷启动路径）
    if (window?.Content == null)
    {
        // ★ 协议冷启动也是这么做的（见 HandleActivation 386-387 行）
        var app = Windows.UI.Xaml.Application.Current as App;
        if (app != null)
        {
            app.OnLaunched(null!);  // 重建整个 UI 树
        }
        return;
    }
    
    // 窗口已经活着且有内容：把它激活到前台
    window.Activate();
}
```

**关键修复点（1.0.81 后续修复）：**
- **问题**：最初实现只调用 `window.Activate()`,如果应用被完全终止后点击通知,会显示一个只有 logo 的空窗口
- **根因**：Reactor 的 UI 树是在 `OnLaunched` 中创建的,冷启动时如果不走这个流程,窗口就没有内容
- **修复**：检测 `Window.Current.Content == null` 时,调用 `app.OnLaunched(null!)` 重建整个 UI 树,这与协议激活的冷启动路径完全一致

```csharp
    var window = Windows.UI.Xaml.Window.Current;
    if (window != null)
    {
        window.Activate();
        RollingLog.Info("toast", "已将主窗口激活到前台");
    }
}

/// <summary>从 Toast 按钮触发断开连接</summary>
private static async void TriggerDisconnectFromToast()
{
    var result = await ClashUWP.Backend.VpnSession.DisconnectAsync();
    RollingLog.Info("toast", $"Toast 断开连接结果: {result}");
}
```

## 3. 行为对照表

| 用户操作 | 旧版（1.0.80） | 新版（1.0.81） |
| --- | --- | --- |
| **点击通知主体** | 什么都不发生（静默通知没有默认激活行为） | 主窗口被激活到前台，通知仍留在通知中心 |
| **点击"断开连接"按钮** | 无此按钮 | 通知进入 pendingUpdate 状态 → 调用 DisconnectAsync → Stop() Hide 掉通知 |
| **手动划掉通知** | 计额度、补发、发引导通知（最多 3 次） | 行为不变 |
| **系统按寿命撤下（TimedOut）** | 只记账，不清 _shown，继续 Update | 行为不变 |
| **实时更新网速** | 每秒读计数，变了才 Update | 行为不变 |

## 4. 未验证项（真机头实测前必须知道）

| 验证项 | 风险等级 | 说明 |
| --- | --- | --- |
| **点击通知主体能否真正激活窗口** | 中 | UWP 的 `Window.Activate()` 在后台/挂起状态下是否有效需实测 |
| **pendingUpdate 状态的视觉效果** | 低 | 官方文档说会显示"加载指示器"，但实际长什么样需实测确认 |
| **点击按钮后通知是否真的不消失** | 中 | `hintAfterActivationBehavior` 是较新的属性，26100 投影里是否有需验 |
| **DisconnectAsync 完成后通知是否被正确 Hide** | 中 | Stop() 里的 Hide 逻辑没变，但要验"pendingUpdate 状态下 Hide 会不会报错" |
| **循环在 pendingUpdate 期间继续 Update 的行为** | 低 | 理论上 Update 会把 pendingUpdate 状态恢复正常，但需实测确认 |

## 6. 官方口径存档

- [Toast schema - launch attribute](https://learn.microsoft.com/zh-cn/windows/apps/develop/notifications/app-notifications/toast-schema)："`launch` 属性指定当用户点击 toast 时传递给应用的参数字符串"
- [Toast schema - hintAfterActivationBehavior](https://learn.microsoft.com/zh-cn/windows/apps/develop/notifications/app-notifications/toast-schema)："`PendingUpdate` — 用户点击按钮后，通知保持'待更新'视觉状态，应立即从后台任务更新该通知"
- [App notification activation](https://learn.microsoft.com/en-us/windows/apps/develop/notifications/app-notifications/app-notifications-quickstart)："Setting activationType='background' in the notification XML payload is ignored for desktop apps. You must process the activation arguments in your code"
- [Toast activation types](https://learn.microsoft.com/zh-cn/windows/uwp/design/shell/tiles-and-notifications/send-local-toast)："前台激活（activationType='foreground'）会调用应用的 OnActivated 方法"

## 7. 纪律

- 这里**不碰隧道、不碰网络、不碰内核**：只改通知的激活行为和 UI 交互
- 断开连接的逻辑复用现有的 `VpnSession.DisconnectAsync()`，不在通知层重写一套
- 循环刷新逻辑完全不变：仍然是"变了才 Update"，避免无意义的平台调用
