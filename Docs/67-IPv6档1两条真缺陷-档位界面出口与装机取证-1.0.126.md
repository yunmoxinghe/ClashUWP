## 二、缺陷 ① 生产端按族筛 —— 档 1/2 的自环黑洞

### 2.1 旧代码三处，逐字

| 位置（修前） | 原文 | 后果 |
| --- | --- | --- |
| `Vpn/NodeRoutes.cs` 类注释 | 「IPv6 节点不处理 —— 本插件只下发 IPv4 路由，v6 出站天然走物理网卡，不构成自环」 | 这句话在 `ipv6=0` 下是对的，在档 1/2 下**正好反了** |
| 存台账（旧 :231） | `if (literal.AddressFamily == AddressFamily.InterNetwork)` ⇒ else `map[host] = new List<string>();`，注释「IPv6 节点：v4 隧道不捕获，留空占位避免每次重连再解析」 | v6 字面量存成**空列表**（=§一 那三行） |
| 域名解析（旧 :265） | `.Where(a => a.AddressFamily == AddressFamily.InterNetwork)` | AAAA 全丢，域名型节点也产不出 v6 候选 |

### 2.2 为什么 arm=0 无害、arm=1 致命

档 1 往隧道里下发的 include 是 `2000::/3` —— 它覆盖**全部全局单播 v6，包括 v6 节点服务器
自己的地址**。防自环那道路由层防线（节点地址的宿主路由排除）如果在生产端就被族别筛掉，
那么"订阅里有 v6 节点 + `ipv6=1`"这个组合下，内核拨向该节点的外层包命中自家 include、
被自己的隧道抓回去，**没有任何排除路由兜它** —— 形态就是 Docs/08 记过的那类自环黑洞。

`arm=0` 时两个 v6 桶本来就是空的（`RouteInclusion.Build` 按名丢弃），所以跳过 v6 排除
无副作用。这条错只在抬档时咬人，而两档从未实机跑过 ⇒ 它躲过了所有装机取证。

### 2.3 ★ 订正 Docs/22 §9.1 的口径：1.0.119 那批只修了消费端

§9.1 当时列的两处**确实都改了**（`ClashVpnPlugin.BuildRoutes` 里写死的
`address.IndexOf(':') < 0` 整段搬进 `RouteInclusion`；`/32` 统一拼接换成按族取
`HostRoute`），但它据此写下的这一行是**按"路径通顺"推出来的，不是跑出来的**：

> 现在（`RouteInclusion.Build`）：arm≥1 → 节点 v6 地址作为 /128 进 Ipv6ExclusionRoutes

消费端收得到，**生产端交不出** —— §2.1 那两处存台账/解析时的族别筛当时一处没动。
1.0.119 的夹具也没能拦住：它往 `RouteInclusion.Build` 里**手喂** v6 排除串，
于是夹具全绿、产品那条链断在喂串之前。这是"夹具只钉纯函数、不钉生产端能不能产出这个输入"
的盲区，本批第 6 条端到端判据专门补这一维。

### 2.4 修法

- `NodeRoutes.cs:234` / `:269`：两个族**一律存进台账**（字面量 v4/v6 都存，域名解析保留
  v4 + AAAA）；其他族才留空占位。
- 台账 → 候选这一步搬成纯函数 `RouteInclusion.HostRouteCandidates(addresses, max)`
  （`RouteInclusion.cs:284`）：跳过空串、大小写不敏感去重、到 `max` 立刻收口、
  前缀长度按族取（v4 `/32`、v6 `/128`）。**族别只决定前缀长度，不决定要不要产出。**
- "arm=0 不拿 v6 排除"这个决定**只留给 `Build` 一处**做，并且按名出声丢弃。
  两处各筛一套必然漂移 —— 这次的漂移就是这个形状。
- `NodeRoutes.cs:96` 变成一行委托调用，去重与上限截断也一起进同一个纯函数，判据在夹具里钉。

## 三、缺陷 ② 档 1 的内核 v6 形态取决于订阅原文

### 3.1 旧代码

`Vpn/KernelConfig.cs`（修前 :108）：

```csharp
if (ipv6Arm >= 2)
    EnsureTopLevelIpv6(lines);
```

也就是说档 1 对顶层 `ipv6:` **一个字节都不碰**，只保证"不写 true"。订阅原文自己写了
`ipv6: true`，内核就照样开 v6、照样答 AAAA、照样转发。

### 3.2 三条后果

1. **同一个档 1 在不同机场下内核能力不同** —— 而"内核不答 AAAA"正是档 1 区别于档 2 的定义；
   这一半语义交给订阅原文决定，等于档 1 没有定义。
2. **档 2 用过再降回 1，磁盘上留着上一轮写的 `true`** —— 降档降不掉内核形态。
3. 取证时"档 1 的形状"没法当判据：读回来 `ipv6=true` 分不清是档位写的还是订阅写的。

### 3.3 修法

```csharp
if (ipv6Arm >= 1)
    EnsureTopLevelIpv6(lines, ipv6Arm >= 2);   // KernelConfig.cs:114
```

`EnsureTopLevelIpv6` 收 `wantV6` 参数（`:260`），写 `"ipv6: " + want`；已有键且值是标量就改写，
值为空（块形状）则不动 —— 不拿 YAML 冒险这条口径没变。

★ **档 0 仍然一个字节都不碰**：那是"默认档与 1.0.69 逐字一致"的凭据，夹具第 8/9 条
专门钉它（第 9 条连"订阅自己写了 true"也不碰）。
★ **只动顶层第 0 列那一行**：`dns:` 块里的同名 `ipv6` 字段是另一个东西
（那是"DNS 要不要监听 v6"），夹具用"顶层只有一行 + 原文里那行缩进的 `    ipv6: false` 还在"
两头证明既没重复也没误伤。

## 十二.5 因果订正（本轮最重要的一条纪律）
