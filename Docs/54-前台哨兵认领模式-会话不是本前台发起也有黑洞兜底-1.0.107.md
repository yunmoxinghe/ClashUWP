# Docs/54 · 前台哨兵认领模式（1.0.107）：会话不是本前台发起也有黑洞兜底

日期：2026-10-23。关账条目：[Docs/53 §五.⑥.2](53-关窗2秒断联-臂A臂B注册期被拒-臂C把插件宿主挪到第二个Application入口已修好-1.0.102实验-1.0.106修复.md) 列的"本轮唯一新暴露的面"。

## 一、要修的是什么

前台健康哨兵（`HealthMonitor`）原先只有两条武装路：UI 连接按钮（`VpnSession.ConnectAsync`）与
debug-cmd connect —— 都是"本前台发起拨号"的形状。于是凡**会话不是本前台拨的**，前台就没有任何黑洞兜底：

| 形状 | 旧行为 |
| --- | --- |
| 快速设置面板点连接 | 插件收到 `IVpnPlugIn.Connect`，前台只靠 3 秒轮询事后跟上（1.0.62 起）；哨兵不武装 |
| 平台自发重拨（RasMan） | 同上 |
| 臂 C（1.0.106）无头长期在线，之后重开 app | 前台进程是新的，哨兵随旧前台进程死了；轮询能看到 Connected，但不武装 |

臂 C 之后无头会话可以长期在线，这条暴露面从"理论缺口"变成了"主路径"——无头期间只有插件侧
`physical-watchdog-plugin` 在兜，前台的探针判黑、重拨保险丝、物理兜底三条判据全部缺位。

## 二、联网对齐的最佳实践

- **Cisco AnyConnect（官方管理员指南）**：Auto Reconnect 默认启用、强烈建议不改；配合 TND
  （受信网络检测）**持续监测连接状态**并在断开时自动动作 —— 状态监测与"谁发起的连接"无关。
- **腾讯云 VPN 通道健康检查**：连续 N 次探测失败才判定不健康并动手（抗抖动）。
- **Azure 虚拟桌面 fast reconnect**：检测传输失败 → 指数退避重试，全程判据驱动。
- 共同口径：**健康监测跟着会话状态走，与发起者无关；动手要连续多次失败才动手**。
  后半句本仓已有（连续两轮探针失败 + 判据不可信绝不动手，1.0.78 口径），缺的只是前半句的"跟着会话走"。

## 三、改动（1.0.107）

★【1.0.119 订正】本节把"有没有硬上限"当成 `AdoptArm` 与 `Arm` 的**第一条**差别，这条已经过期：
1.0.119 把 1800 s 无条件兜底从**两条路一起删掉**（到点强拆健康隧道 = 用户视角"每半小时自己掉线"，
认领路径只是先把这件事说破）。此后两条路的真差别只剩一条 —— 重拨基线里有没有"我们自己那一次"。
删改的逐条落点与三处日志文案口径见 **Docs/62 §1.1–1.2**，装机前后对照见 **Docs/62 §6.5**；本文 §五 那张取证表是
1.0.107 当时的实物，按"历史证据不改写"的规矩留着，读的时候按本节订正理解（那几行日志里带「上限 1800s」「上限 2147483647s」的句子在 1.0.119 之后都不再出现）。

### ① `HealthMonitor.AdoptArm()` —— 认领模式

与 `Arm()` 同一条 `RunCoreAsync`，两点差别，都源自"这次没有我们自己的拨号"：

1. **没有硬上限**。1800 s 上限是"先武装再连接"那条路的保险丝，防的是拨号悬挂长期占网；
   认领的会话在武装那一刻已经 Connected 且健康，到点强拆健康隧道 = 用户视角"每半小时自己掉线"。
   收尾判据只剩四条，全是判据驱动：探针连续两轮国内不可达 / 重拨保险丝 / 物理兜底 / 会话消失出口。
2. **重拨基线里没有"我们自己那一次"**：`unmanaged = connects - 0`。否则每次平台重拨被少记一次，
   828 死循环要多熬一轮才拆。

### ② 探测循环内加"会话消失出口"

每轮顺带读一次状态（限时 3 s，同前置确认口径）；**连续两轮终态**（Disconnected / Profile缺失）
⇒ 会话已经不在了，哨兵退出，**不断开不删 profile**。

- 为什么要：旧循环条件只有 deadline 与探针。会话被快速设置断开后，哨兵继续在**直连网络**上探到
  硬上限，然后 Disconnect + DropProfile —— 删掉的恰是承载快速面板条目的基础 profile
  （"条目自己消失"形状，Docs/30 §8-A 同族）。这也是一条潜伏 bug，与暴露面同源同修。
- 认领模式没有硬上限，不补这条就会在死会话上永远探下去。
- 连两轮才认：给 RasMan 正常重拨的中间态让路；退出只是"停止保护"不是"动手破坏"，
  会话回来时轮询会重新认领 —— 代价不对称性成立。

### ③ `VpnSession.AdoptLiveSessionIfUnprotected()` + 轮询接线

3 秒轮询读到 `Connected` 且 `!HealthMonitor.IsActive` ⇒ 认领。已有哨兵时是空操作 ——
Arm 语义是"顶掉再武装"，重复认领**不许**把既有 1800 s 保险丝顶成无上限的认领哨兵。
接线点在 `MainComponent` 轮询 `_setVpnStatus(status)` 之后；判据不可信不动手的闸原样保留。

## 四、与既有纪律的对照

- 「判据不可信绝不动手」：认领哨兵的收尾四条判据全部继承 1.0.78 口径，无一新增裸探。
- 「先武装再连接」：连接按钮路径原样未动；认领只发生在"会话已在"的观测点上。
- 「profile 只在已判死才删」：认领模式的会话消失出口**不删**；探针判黑的收尾仍是"曾 Connected"
  的会话，与 1.0.78 收窄一致。
- 1.0.88 那条"多点一下按钮不摘保护"：认领是空操作当哨兵已在，方向一致。
