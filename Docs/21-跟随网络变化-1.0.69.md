## 2. 缺口是什么形状（不是"没有功能"，是"绑定会陈旧"）

我们的防自环靠一条**按网卡名**的绑定：桥启动时探测物理网卡，把名字存进
`dialer.DefaultInterface`（`Tools/mihomo-bridge/bridge/core.go:105-120`），
Windows 实现是每次拨号时用它查 `iface.ResolveInterface` 并设 `IP_UNICAST_IF`
（`component/dialer/bind_windows.go:81-100`）。

两条会把这条绑定弄坏：

1. **只在 `Bridge.Start` 里跑一次探测。** `rebindInterface()` 的两条调用路径是
   首次启动 `core.go:153` 和"已启动"分支 `core.go:132-137`。会话中途
   Wi-Fi 切有线、路由器重连、热点断开，名字对应的接口已经消失/换了归属 ——
   绑定仍是连接那一刻的值。
2. **任何一次热重载都会把绑定清空。** `hub/executor/executor.go:412`
   无条件执行 `dialer.DefaultInterface.Store(general.Interface)`，而我们生成的
   配置里没有 `interface-name`（值 = 空串）。⇒ `PUT /configs?force=true`
   成功之后，防自环绑定事实上被撤掉。

本批两条都补，且都不改 Go、不重编 DLL。

## 3. 三档与默认

| 档 | 行为 | 代价 |
|---|---|---|
| 0 | 完全不订阅（本批之前逐字一致） | —— |
| **1（默认）** | 订阅 `NetworkStatusChanged` → 5 s 合并 → 比对指纹；变了就**作废节点路由缓存**并记日志。**不动桥、不发 HTTP** | 一次事件评估只读几个属性 + 写一行日志 |
| 2 | 在 1 之上：指纹真变化就**请求桥重绑**（30 s 限频、5 次/会话上限） | 再调一次 `clash_bridge_start`，命中的是 Go 的"已启动"分支，不 Parse 配置、不 ApplyConfig |

★ 默认停在 1 的理由（与 `EncapReturn` 档 5、`SessionReset` 档 1/2 同一口径）：
**两条前提都还没读回来** —— ① `NetworkStatusChanged` 在 vpnClient 后台任务进程里
收不收得到；② "同进程第二次 `clash_bridge_start`"在本项目有前科（Docs/05 §2④，
桥常驻就是为了绕开它）。档 1 的日志行正是把 ① 读回来的手段。

## 4. WinRT 能力面核对：三个按记忆写的 API 全是错的

这一节是本批最值得留档的部分。第一稿按记忆写了
`NetworkInformation.NetworkAdded / NetworkRemoved / NetworkChanged` 与
`NetworkChangedEventArgs`、`NetworkAdapter.GetDnsServers()/IsConnected`、
`NetworkConnectionProfile` —— **编译期全部报错**。随后用
`ilspycmd` 反编译本机 SDK 的 winmd（`...\10.0.26100.0\...\19.0.0.0\Windows.Foundation.UniversalApiContract.winmd`）逐项核对：

| 记忆里的写法 | winmd 实际 | 后果 |
|---|---|---|
| `NetworkAdded/Removed/Changed` 事件 | **不存在**；`NetworkInformation` 的事件表**只有** `NetworkStatusChangedEventHandler` | `NetworkFollow` 只订阅这一个事件；"哪张卡变了"由指纹前后值回答 |
| `NetworkChangedEventArgs` | 不存在 | 同上 |
| `NetworkConnectionProfile` | 类名是 `ConnectionProfile` | 已改 |
| `GetCurrentNetworkConnectivityLevel()` | 是 `ConnectionProfile.GetNetworkConnectivityLevel()` | 已改 |
| `NetworkConnectivityLevel.NoInternet` | 枚举只有 `None / LocalAccess / ConstrainedInternetAccess / InternetAccess` | 已改 |
| `NetworkAdapter.GetDnsServers()` | **不存在**（`NetworkAdapter` 只有 `IanaInterfaceType`、`Inbound/OutboundMaxBitsPerSecond`、`NetworkAdapterId`、`NetworkItem`、`GetConnectedProfileAsync`） | **指纹里没有 DNS**，也不假装有；"换网后 DNS 变没变"在插件进程里观测不到 |
| `NetworkAdapter.IsConnected` | 不存在 | 已删 |
| `NetworkItem.Name` | 不存在（只有 `NetworkId` + `GetNetworkTypes()`） | 已改为 `NetworkId` |
| `ConnectionProfile.NetworkItem` | 不存在 | Internet 链路身份改为 `ProfileName + NetworkAdapterId` |

⇒ 指纹的最终形状（`NetworkFollow.Fingerprint`）：
`lvl=… internet=ProfileName[adapter8] n=… [adapterId type=IANA net=networkId8] … addrs=ip@adapter8,…`
（900 字节封顶，截断可见）。

同时，原实现里"把 DNS 变化记进日志"这句话也撤掉了 —— **不以有能力的姿态写注释**。

`NodeRoutes` 那一条是"作废"的闭环：只打标记不消费就是死代码。
标记的语义是"这批结果是在**上一个网络**里量出来的"，所以它**优先于 TTL**；
解析失败的 host 保留旧值（类注释原口径），标记留到下一次连接再试。

## 6. 证据怎么读

- 组件日志 `logs/plugin.log`，`channel=net-follow`：
  - 武装：`武装 arm=1 … bound_iface=WLAN 基线=lvl=InternetAccess internet=…`
  - 事件：`evt=NetworkStatusChanged 指纹=变了/未变 bound=旧→新 …`
  - 档 2：`重绑（net-follow:…）结果=已启动→已重绑 rc=-2 bound=旧→新 用时=…ms`
  - 热重载补绑定：`channel=iface-bind` 的 `PATCH interface-name=… -> 2xx`
- sessions 汇：`evt=net-follow …`、`evt=net-rebind …`、`evt=iface-bind …`
  （尾部追加，不改既有列）。
- 快照 `dataface-plugin.txt`：`NetFollow=` / `NodeCache=`。

判读口径：
- 有"武装"行、**一次事件行都没有** ⇒ 事件在后台任务进程里收不到（前提 ① 不成立），
  档 2 在此环境下也不会有动作；G6 退回档 0 的等价状态（不碰桥）。
- 有事件、`指纹=未变` ⇒ 事件到了但判据没看见变化（可能是事件在指纹无关的变化上触发）。
- `bound=空→空` ⇒ 桥侧探测失败（**这本身就是断网风险的证据**，不是 G6 的错）。
