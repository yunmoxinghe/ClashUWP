# 07 · 宿主恢复手册（装包与隧道实验的前置兜底）

本项目的实验会动到宿主的 DNS / 路由 / VPN profile，一旦半途而死（进程被杀、臂超时、
机器被远程锁在外面），必须有一条**不依赖主流程跑完**的恢复路径。
本文件就是那条路径：命令逐条列出，随时可单独执行。

纪律：不自制部署 ps1（AGENTS.md 规则 2）。部署与卸载只走 VS 生成的
`AppPackages\...\Add-AppDevPackage.ps1`；下面这些是**恢复与取证**动作，不是部署。

---

## 0. 三层恢复，按代价从小到大

| 层 | 触发条件 | 动作 | 谁来按 |
|---|---|---|---|
| L1 自动 | 隧道黑洞 | 应用内健康哨兵：10 s 一轮，**连续 2 轮**国内 IP 探针（`223.5.5.5:443`、`119.29.29.29:443`，都是 IP 字面量不依赖 DNS）全失败 → 自动 `DisconnectAsync()`；另有**硬上限 600 s 到点必断**，不依赖任何判断 | 已经跑在包里，无需干预 |
| L2 手动断开 | 哨兵没跑起来 / 想提前收 | `rasdial "ClashUWP" /delete`（顺带拆连接 + 删 profile），探针 profile 是 `rasdial "ClashUWP-Probe" /delete` | 用户或 agent 获准后 |
| L3 强拆 | profile 已删但 **NRPT 残留**（最危险：DNS 被指向已经不存在的隧道地址 = 整机解析瘫痪） | 见下面 §2 | 需要管理员，通常要用户亲自动手 |

**L3 是本手册存在的全部理由。** 先遣项目 docs/99 §8.5 的事故就是这一类：
VPN 插件进程已经死了、网卡也没了，但 NRPT 还在把整机 DNS 指到一个不存在的地址，
`Test-NetConnection baidu:443 = False` —— 对正在远程用这台机器的人，
这跟断网没有区别。PowerShell 的 `try/finally` 挡不住进程被杀，所以不能只靠改主流程。

## 1. 判据（收尾必须跑，且如实报告）

```powershell
(Get-DnsClientNrptRule -ErrorAction SilentlyContinue | Measure-Object).Count   # 应为 0
Get-NetRoute -DestinationPrefix '0.0.0.0/0' | Select-Object InterfaceIndex,NextHop,InterfaceMetric   # 应只剩物理网卡（本机 WLAN idx=6 metric=35）
Get-VpnConnection -AllUserConnection -ErrorAction SilentlyContinue | Select-Object Name,ConnectionStatus  # 应为空
Test-NetConnection baidu.com -Port 443                                          # TcpTestSucceeded 应为 True
```

四条里任何一条不对，就继续往下走 L3，**不要**带着残留去干别的。

## 2. L3：强拆 NRPT

```powershell
# 以管理员身份
Get-DnsClientNrptRule | Format-Table Name,Namespace,NameServers -AutoSize
Get-DnsClientNrptRule | Remove-DnsClientNrptRule -Force
```

只信 `Get-DnsClientNrptRule` 的实际返回值，不信任何 API 的"成功"——
插件进程不在时上层 API 常常只是假装成功（docs/99 §8.5）。

## 3. 卸载（代价：连带删掉 LocalState，取证文件一起没）

包目录里是 VS 自己的脚本，卸载也优先用 VS（IDE 里「部署」的反向操作或 `/Deploy`）；
`Remove-AppxPackage` 是**最后手段**：本包带 `vpnClient` 后台任务、连接对象挂在 RasMan 里，
Remove 可能卡住，脚本超时时**不要 kill**（往 AppXSVC 队列里堆 `0x80073CF8` 尸体，
下一轮更难返回）—— detach，not kill。

⚠️ 卸载会清空 `LocalState`：`config.yaml`、`dataface-plugin.txt`、`tun-sample.txt`、
`probe.txt`、`debug-cmd.txt` 全在里面。**要取证就先备份，再卸载**。
本机路径（1.0.16 实测有效，包家族名见 §4）：

```
C:\Users\gold\AppData\Local\Packages\421769c5-17f4-4287-b6c1-193222d21e14_y0tg80em3rma2\LocalState
```

里面有 `config.yaml` / `dataface-plugin.txt` / `tun-sample.txt` / `probe.txt` /
`profile-dump.txt` / `health.txt` / `settings.txt` / `debug-cmd.txt`（写入即被 1 s 内的
轮询取走）/ `rasphone.pbk`。

## 4. 1.0.16 装包前后的实测记录（差分基线）

⚠️ **取包名的坑**：清单 `<Identity Name>` 是 GUID（`421769c5-17f4-4287-b6c1-193222d21e14`，
Publisher `CN=gold`），不是 `ClashUWP` —— `Get-AppxPackage | ? Name -like "*Clash*"`
**永远返回空**，会把"装着呢"读成"没装"（本轮就这么错过一次）。正确姿势：

```powershell
Get-AppxPackage | Where-Object { $_.Name -like "*421769c5*" } |
    Select-Object Name,Version,PackageFamilyName,InstallLocation,Status
```

| 项 | 装包前 | 装包后 |
|---|---|---|
| 已注册包 | `1.0.14.0`（先前记录误写成"0"，见上面的坑） | **`1.0.16.0`**，`Status=Ok`，原地升级 |
| PackageFamilyName | `421769c5-…-y0tg80em3rma2` | 同左（升级不换家族名） |
| NRPT 条数 | 0 | **0** |
| 默认路由 | 仅 idx=6 / 192.168.0.1 / metric 35（WLAN） | **逐字不变** |
| VPN profile | `ClashUWP` ×1，`ConnectionStatus=Disconnected`（`Get-VpnConnection` 查不到，要靠应用自己的 `profile-dump.txt`） | 同左，**没被连接** |
| 百度 443 直连 | True | **True** |
| 签名证书 | `EDF4E8E0A70864E1F82376012ADE32DAD509DE9F` 已在 Machine+User 的 TrustedPeople | 同左 → 脚本 `$NeedInstallCertificate=$false`，**全程不弹 UAC** |

其它两条现场事实：

- 装包成功后 `Add-AppDevPackage.ps1` **自己把应用拉起来了**（pid 27048，
  `reactor-startup.log` 00:50:10 有 RUNTIME OS 行）—— 桌面上会多一个窗口，属预期。
- `clash-verge-service`(pid 5148) 在跑，但**没有** `verge-mihomo` 进程、**没有** Meta TUN 适配器。
  开测前要用 §1 的路由/适配器检查再确认一次：先遣项目 docs/88/90/98 §5.7 点名过，
  另一块 TUN 一出现就会抢 /32 路由并全量劫持 53 端口，把结果读成假 PASS/假 FAIL。

装包本身**不碰路由、不碰 DNS、不建 profile、不连接**（上表差分可证），风险为零；
上面这些是给后面 `connect` 那一轮准备的。`connect / disconnect / recreate / probe`
这类动作未经用户点名，一条都不写、不打。
