## 二、关键缺口优先级排序

### 🔴 P0（严重影响可用性）

#### 1. **实时流量图缺失**
   - **影响**：用户无法直观看到当前网速，不知道隧道是否在工作
   - **CMFA 做法**：首页顶部常驻折线图，每秒刷新
   - **建议修复**：在 MainComponent 顶部加一个简易折线控件，从 `/traffic` REST API 每秒拉数据

#### 2. **订阅健康检查缺失**
   - **影响**：用户不知道哪些节点还活着，只能一个个试
   - **CMFA 做法**：代理页"全部测速"按钮，后台并发 ping 所有节点
   - **建议修复**：加一个"批量测速"按钮，调用内核 `GET /proxies/{group}/delay?url=...` 循环测

### 🟡 P1（影响体验但可绕过）

#### 3. **延迟测试不便**
   - **现状**：需手动敲 `delay` 命令
   - **建议**：UI 加"测速"按钮，一键触发当前组的 URLTest

#### 4. **自动更新订阅缺失**
   - **现状**：需手动点"更新当前订阅"
   - **建议**：设置页加"自动更新间隔"选项，后台定时器定期拉取

#### 5. **订阅元信息不显示**
   - **现状**：只显示节点数/规则数
   - **建议**：解析响应头里的 `subscription-userinfo`（含 `upload`/`download`/`total`/`expire`），显示剩余流量和过期时间

#### 6. **通知栏缺少快捷操作**
   - **现状**：只有静默的↑↓通知
   - **建议**：加快速操作按钮（切模式/断开连接），类似 CMFA 的下拉通知栏

#### 7. **实时日志不可见**
   - **现状**：需手动打开 `logs/app.log`
   - **建议**：设置页加"查看日志"入口，实时 tail 最后 100 行

### 🟢 P2（锦上添花）

8. 节点搜索/过滤
9. 深色模式/主题切换
10. 订阅分组/标签
11. 连接详情展开
12. 历史连接记录
13. Fake-IP 池可视化
14. 日志级别动态切换
15. 导出日志文件
16. 锁屏小部件

## 三、实施建议

### 短期（1.0.73~1.0.75）

优先补 **P0 + P1** 中实现成本低的：

1. **实时流量图**（P0）
   - 复用现有 `/traffic` REST API
   - WinUI 画一个简单的折线控件（或直接用 Canvas 手绘）
   - 每秒刷新，保留最近 60 个点

2. **批量测速**（P0）
   - 代理页加"全部测速"按钮
   - 对当前选中组的每个成员调 `GET /proxies/{name}/delay?url=http://cp.cloudflare.com`
   - 并发限制 10 个，避免把内核打挂

3. **订阅元信息显示**（P1）
   - FetchAsync 解析 `subscription-userinfo` header
   - 持久化到 settings.txt（`subQuota:{id}=upload,download,total,expire`）
   - UI 显示"已用 X GB / 总共 Y GB，过期时间 Z"

4. **自动更新订阅**（P1）
   - 设置页加 ComboBox："不自动更新 / 每 6 小时 / 每 12 小时 / 每天"
   - 后台定时器（UseEffect + Task.Delay）定期检查
   - 只在未连接时更新，避免打断隧道

### 中期（1.0.76~1.0.80）

补剩下的 **P1**：

5. **通知栏快捷操作**
6. **实时日志查看器**
7. **延迟测试一键触发**

### 长期（1.0.81+）

按需实现 **P2** 功能，优先级取决于用户反馈。

## 四、与 Verge Rev 的对齐

ClashUWP 的设计哲学是 **"Verge 式原地切换"**（热重载配置、不断开隧道），这与 CMFA 的"重连式切换"不同。因此：

- ✅ **保留的优势**：切换订阅不断线、应用分流（ACL）、系统 VPN profile 原生集成
- ⚠️ **需要补齐的短板**：实时反馈（流量图/日志）、自动化（自动更新/批量测速）

**核心原则**：不动内核（mihomo），只在前台/后端补 UI 和自动化逻辑。

## 五、一句话总结

ClashUWP 1.0.72 在**订阅同步/系统 profile 集成/应用分流**上已经对齐甚至超越 CMFA，但在**实时反馈（流量图/日志）**和**自动化（批量测速/自动更新）**上仍有明显缺口。下一步应优先补这两块，让用户体验从"能用"升级到"好用"。
