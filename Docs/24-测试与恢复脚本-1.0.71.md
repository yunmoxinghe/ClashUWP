# 24 · 测试与恢复脚本（1.0.71）

批次标记【1.0.71】。用户原话：**「然后用脚本做测试，准备好提前恢复网络脚本」**。
本文是这一批的交付说明：**离线测试**、**上机取证**、**网络恢复**三套脚本，
以及装包后按 G6 / G7 / DNS 三条线执行的验收矩阵。

> ★★ 本批仍**整机零验证**：用户在 school，装着的仍是 `1.0.64.0`
> （22:21 的取证脚本自己读出来的），1.0.71 的 MSIX 已构建好但没装。
> 脚本的价值是"用户回来装包后，每一步都有可复现的取证与兜底"，
> 不是"已经跑过一遍"。

## 0. 纪律（脚本不碰什么）

| 脚本 | 会写吗 | 边界 |
|---|---|---|
| `Tools\run-offline-tests.cmd` | 只写 `bin/obj` 编译产物 | 不联网、不装包、不读写 LocalState |

这三套脚本都不是部署脚本 —— 不违反 AGENTS.md 的第 2 条。

## 2. 上机取证（只读）

```powershell
# 控制台输出
powershell -NoProfile -ExecutionPolicy Bypass -File Tools\TestScripts\collect-evidence.ps1

# 同时落盘（便于回传）
powershell -NoProfile -ExecutionPolicy Bypass -File Tools\TestScripts\collect-evidence.ps1 -OutFile C:\temp\clashuwp.txt

# 连 DNS 查询都不发
... -SkipDnsProbe
```

输出分十段：包与 LocalState、`settings.txt`、`dns-config.txt`、`split-apps.txt`、
`dataface-plugin.txt`、`config.kernel.yaml` 的 `ipv6/dns/tun` 块、logs（最后 80 行）、
VPN 两个 profile 存储、NRPT 规则与策略、ClashUWP 接口/地址/路由、幽灵路由、
系统解析器 A/AAAA、判读提示。

★ 三个刻意的取舍：

1. **订阅 URL 打码**：`settings.txt` 里 `subUrl:…=https://…` 的 token 段替换成
   `(redacted)`，取证文件可以直接贴出来。
2. **不用 `Get-NetAdapter` 判断 VPN 接口**：它看不见 VPN 的 Ppp 接口
   （memory「VPN forensics metric traps」）；脚本用 `Get-NetIPInterface` /
   `Get-NetIPAddress` / `Get-NetRoute`。
3. **只发一个域名的 A/AAAA 查询**（`www.google.com`）。这是看门狗判据②的同款路径，
   用来确认"解析答案是否落在假 IP 池里"；不加测速、不灌流量。

### 2.1 关键证据行怎么读

| 证据 | 含义 |
|---|---|
| `Version=1.0.71.0` | 装的是本批的包；还是 1.0.64 = 没装成功 |
| `dataface-plugin.txt` 的 `Ipv6=arm=0 未下发` | G7 档 0 与旧行为逐字一致 |
| `Ipv6=arm=2 addr=… routes=[…] pool=…` | 档 2 现场；`pool` 带 `(dns-config 覆盖)` 时说明 v6 池来自文件 |
| `Dns=无覆盖` / `应用 N 项…` / `总闸关闭（dnsConfig=0）` | 内核侧 DNS 覆盖结果 |
| `DnsIntoTunnel=1 (…) nrpt=dns-config 覆盖` | NRPT 实际服务器与来源 |
| `dnsCfg=N项 fakePool=…` | 本次连接的 DNS 覆盖规模与生效 v4 池 |
| `NetFollow=…` | G6 最近一次评估（事件名/指纹变没变/动作） |
| `fake-ip=OK:… pool=…` | 看门狗判据②；`NO` 连续 10 次会拆隧道 |
| NRPT 规则 `Namespace=.` 且 DNS 是隧道 DNS | **孤儿 NRPT 的形状**（断开后不该存在） |
| ClashUWP 路由 / 幽灵路由 | 断开后都应为 0 |

## 3. 网络恢复（兜底）

```powershell
# 1) 先看（不需要管理员，只列清单）
powershell -NoProfile -ExecutionPolicy Bypass -File Tools\TestScripts\restore-network.ps1

# 2) 执行（管理员）
powershell -NoProfile -ExecutionPolicy Bypass -File Tools\TestScripts\restore-network.ps1 -Execute

# 3) 名字匹配不到、但确实只剩根 NRPT（核选项：删所有 NRPT 规则）
... -Execute -AllNrpt

# 4) VPN 仍显示 Connected 但整机已断（强拆路由）
... -Execute -Force
```

### 3.1 它怎么判"残留"

- **NRPT 候选**：`Get-DnsClientNrptRule` 里满足
  `Namespace` 含 `.`（根规则）**且**（`Name`/`DisplayName`/`Comment` 命中
  `ClashUWP` 或包 GUID，**或** `NameServers` 含 `223.5.5.5`/`119.29.29.29`）。
  `-AllNrpt` = 不看条件，删全部规则。
- **路由候选**：`InterfaceAlias -like '*ClashUWP*'` 的 ActiveStore +
  PersistentStore 路由，按 `ifIndex|前缀|下一跳|store` 去重。
- 执行前若检测到 ClashUWP VPN 仍是 `Connected`，**拒绝删除**（除非 `-Force`）——
  避免把一条还活着的隧道拆了。
- 执行后复核：重列候选、`Clear-DnsClientCache`、`Resolve-DnsName www.baidu.com`。
  退出码 `0` = 未发现残留；`1` = 仍有残留/删除失败；`2` = 没管理员；
  `3` = VPN 还连着、拒绝执行。

### 3.2 它刻意不做

不装/不卸/不打包、不连接/断开、不删 VPN profile、不改全局 DNS、不重置网络栈、
不禁用网卡。**"网络重置"是最后手段**：它会清掉本脚本想保留的现场。

### 3.3 什么时候该用它

只在"断开 VPN 后域名不通、IP 字面量能通"或"整机断网且看到根 NRPT/幽灵路由"时用。
正常断开后 `collect-evidence.ps1` ≈ `NRPT 候选=0`、`路由候选=0` 就什么都不用做。

## 4. 上机验收矩阵（装 1.0.71 之后）

前置：双击 `ClashUWP/AppPackages/ClashUWP_1.0.71.0_x64_Test/ClashUWP_1.0.71.0_x64.msix`
安装（PowerShell `Add-AppxPackage` 在本机不可用；也不要拿"重新安装"去解
`0x80073CFB` —— 那是同版本重装，需 bump 版本，见 memory）。
装完先跑一次 `collect-evidence.ps1` 确认 `Version=1.0.71.0`。

### 4.1 基线（默认：`ipv6=0`、`netFollow=1`、`dnsConfig=1`、无 dns-config）

1. 连接 VPN；跑 `collect-evidence.ps1`。
2. 预期：
   - `Ipv6=arm=0 未下发`；
   - `Dns=无覆盖`；`DnsIntoTunnel=1 (223.5.5.5,119.29.29.29) nrpt=profile`；
   - `fake-ip=OK:… pool=198.18.0.0/16`（plugin.log）；
   - `Resolve-DnsName www.google.com A` 得到 `198.18.x.x`；
   - ClashUWP 接口只有 v4 地址。
3. 断开；再跑证据：NRPT 候选=0、ClashUWP 路由=0、`resolve www.baidu.com` 正常。

### 4.2 G6 跟随网络

1. 连接（默认 `netFollow=1`，只观测）；记下 `NetFollow=`。
2. **用系统托盘的 Wi-Fi 开关**切一次（Software Radio）。
   ★ 不要禁用网卡、不要删路由/网络重置 —— 会连带打断蓝牙（memory）。
3. 30 s 内预期：
   - app.log / plugin.log 出现 `channel=net-follow` 的评估行（`changed=1`）；
   - `dataface-plugin.txt` 的 `NetFollow=` 更新；
   - 隧道不断，`Resolve-DnsName` 仍是假 IP。
4. 想验档 2（重绑）才把 `settings.txt: netFollow=2` 再连一次；切换后看
   `net-follow` 的重绑日志与 `bound_iface` 前后值。★ 这是 Docs/12 §2 留下的
   "同进程第二次 `clash_bridge_start`"未验前提，失败就把档位写回 1 并留日志。

### 4.3 G7 IPv6（需要一台**有全局 IPv6** 的网络）

本机没有 v6，这一节**不能在本机下结论**。档位写在 `settings.txt: ipv6=0|1|2`，
改档后断开再连。

1. 档 1：接口出现 `fd66:6:6600::2` 与 `fe80::`；出现 `2000::/3` 路由；
   `nslookup -type=AAAA` 空应答；v6 字面量流量进隧道而不是从物理网卡直出。
2. 档 2：`config.kernel.yaml` 有 `ipv6: true`、`dns.ipv6: true`、`fake-ip-range6`、
   `tun.inet6-address`；`Resolve-DnsName -Type AAAA` 返回 `fdfe:dcba:9876::4+`；
   `ipv6.google.com` 能经代理打开；证据里 `Ipv6=arm=2 …`。
3. 两种档位都跑断开收尾：NRPT 候选=0、幽灵路由=0。
4. 任何异常先写 `ipv6=0` 重连（不用重装）；整机断网再上 §3 的恢复脚本。

### 4.4 DNS 可配

路径：设置页「DNS 覆盖」或
`%LOCALAPPDATA%\Packages\421769c5-…\LocalState\dns-config.txt`。

1. **模板**：文件不存在时设置页显示带全部键说明的模板；写
   `nameserver = 223.5.5.5, 119.29.29.29` →「保存并校验」→ "已存 1 项"。
2. **非法值**：`enhanced-mode = redir-host` / `fake-ip-range = 1.1.1.1/33`
   → 保存结果逐条给原因；重连**仍成功**（非法行没进 YAML）。
3. **假池级联**（单变量，最值钱的一条）：
   `fake-ip-range = 198.19.0.1/16` → 断开再连：
   - `config.kernel.yaml: fake-ip-range: 198.19.0.1/16`；
   - ClashUWP 路由出现 `198.19.0.0/16`；
   - `Resolve-DnsName` 返回 `198.19.x.x`；
   - `fake-ip=OK … pool=198.19.0.0/16`，不能出现 `NO`。
4. **NRPT**：`nrpt-dns = 223.5.5.5` + `settings.txt: dnsInTunnel=1` →
   断开再连 → NRPT 策略的 DNS 是 `223.5.5.5`，快照 `nrpt=dns-config 覆盖`。
   ★ 改它后只热重载不换，必须断开重连（Docs/23 §7）。
5. **热重载**：改 `fake-ip-filter` →「订阅 → 重新加载配置」→
   `channel=config` 出现新的 `DNS 覆盖=…`，不断线。
6. **总闸**：`settings.txt: dnsConfig=0` → 重连：
   `Dns=总闸关闭（dnsConfig=0）`，内核与 NRPT 都不动（回到 1.0.70 行为）。
7. **v6 池**（需先开 `ipv6=2`）：`dns-config.txt: fake-ip-range6 = fdfe:1::/64`
   → `v6pool=`、`tun.inet6-address`、include 路由三处同源。

### 4.5 每次收工的固定判据

1. `collect-evidence.ps1` 的 **NRPT 候选=0**、**ClashUWP 路由=0**、**幽灵路由=0**。
2. `Resolve-DnsName www.baidu.com` 正常（不是只通 IP）。
3. 没有自动重拨：`Get-VpnConnection` 两个存储里 ClashUWP 都不是 `Connected`。
4. 出问题先留证据文件，再跑恢复脚本 **dry-run**；确认清单后才 `-Execute`。

## 5. 已知未验证项（脚本也补不了的部分）

1. 1.0.71 的整机行为（连接、DNS 覆盖是否真被内核吃到、NRPT 是否真换）；
2. 本机无 IPv6：G7 档 1/2 的地址/路由/AAAA 只能换网络再验；
3. G6 档 2 的"同进程第二次 `clash_bridge_start`"重绑；
4. `restore-network.ps1` 的 NRPT 名称匹配是启发式：平台规则若既不含
   `ClashUWP` 也不用默认隧道 DNS，只能人工核对后用 `-AllNrpt`；
5. `collect-evidence.ps1` 只采样一次系统解析器，不替代看门狗连续 10 次的判据。
