# 19 · 前端侧边栏与云母（应用 1.0.67）

批次标记【1.0.67】。组件 `ClashUWP.Vpn` 保持 **1.0.34 不动**，本批只改主应用。

## 1. 这一批改了什么，没改什么

需求是一句「先修修 ui，云母加上，侧边栏先放 主页、代理、订阅、设置」，所以本批**只动"怎么摆"，不动"有什么"**：

- 根元素从 `ScrollViewer(VStack(…))` 换成 `NavigationView(…)`，11 个竖着排的区块分到四页；
- 根元素挂 `.Backdrop(BackdropKind.Mica)`，并在设置页给了「云母 / 桌面亚克力 / 无」三档当场对比；
- 删掉 1.0.48 遗留的脚手架（`"Reactor.Uwp 已接管（N）"` 那行标题和 `点一下` 计数器）。

**后端一行没动**：四页上的每个按钮都还是 1.0.48/1.0.6x 那批已有的入口（`VpnSession` / `MihomoController` / `SubscriptionManager` / `KernelView`），本批没有新增任何 REST 调用，也没有新增碰隧道的动作。3 秒轮询还是那一条，挂在挂载时的 effect 上，**切页不重启轮询、不重新读文件**（`MainComponent.cs:239-247`）。

## 2. 外壳：`NavigationView` 四页

| 页 | header | 区块 | 用的入口 |
|---|---|---|---|
| 主页 | 主页 | VPN 控制 / 内核运行态 / 活动连接 | `RecreateAsync`、`ConnectAsync`、`DisconnectAsync`、`KernelView` 快照 |
| 代理 | 代理 | 模式 / 代理组 / 节点 | `RunModeAsync(rule\|global\|direct)`、`GroupPicker`、`MemberList`（纯内核 REST，不碰隧道） |
| 订阅 | 订阅 | 当前生效 / 添加订阅 / 维护 | `SubscriptionPanel`、`FetchSubscriptionAsync`、`UpdateSubscriptionAsync`、`ReloadConfigAsync`、`RefreshSubscriptionsAsync` |
| 设置 | 设置 | 背景材质 / 诊断 / 应用日志 | `MaterialPicker`、`DiagnoseKernelAsync`、`RunConfigsDumpAsync`、`RefreshNowAsync`、`ToggleLogAsync` |

侧边栏条目的图标是**原始字形码**，框架把它直接塞进 `FontIcon.Glyph`（`NavigationViewHandler.FillMenuGroup` 反编译可见）。四个码位是从官方 WinUI-Gallery 的 `WinUIGallery/Samples/Iconography/IconsData.json`（name→code 对照表）逐条查出来的：主页 `E80F` Home、代理 `E774` Globe、订阅 `E896` Download、设置 `E713` Setting。**猜错的码位不报错**，只会画成另一个图标或豆腐块，所以这一条只能靠实机截图收口。

另外两个外壳决定，都是照着控件本意写的：

- `isSettingsVisible: false` —— `NavigationView` 自带一条落在 pane 底部的「设置」第五项，它会报成越界的 `SelectedIndex`。本批的设置就是侧边栏第四项，不需要框架再送一条，所以关掉；`onSelectedIndexChanged` 里也只认 `0..3`。
- `isBackButtonVisible: NavBackButtonVisible.Collapsed` —— 四页平级，没有回退栈，返回键就该收起来而不是灰着占位。

## 3. UWP 上的"云母"走的不是 WinUI 3 那条路

这是本批唯一容易写错的地方，所以把证据链留在文档里。

WinUI 3 的云母是 `Window.SystemBackdrop = new MicaBackdrop()`（官方 `Microsoft.UI.Reactor` 的 `BackdropApplier.Apply` 就是这一句，反编译可见）。**UWP 没有 `Window.SystemBackdrop`**，本包用的 Reactor.Uwp 在 `Reactor.Uwp.Hosting.ReactorHost.ApplyBackdrop` 里换成了 WinUI 2 的主题背景材质：

```
若 BackdropKind 变化：
  记一条 BACKDROP 日志
  BackdropMaterial.SetApplyToRootOrPageBackground(Root, false)
  Mica / MicaAlt        → Root.Background = null; SetApplyToRootOrPageBackground(Root, true)
  DesktopAcrylic        → Root.Background = new AcrylicBrush { BackgroundSource = Backdrop }
  AcrylicThin           → Root.Background = new AcrylicBrush { BackgroundSource = HostBackdrop, TintOpacity = 0.6 }
  None / 其它           → Root.Background = null
```

`BackdropKind.MicaAlt` 在这一条 switch 里和 `Mica` 走同一支（UWP 侧没有 `MicaBackdrop.Kind` 这个东西），这一批不用它。判据不是"我写了 `.Backdrop(Mica)` 所以屏幕上是云母"，而是两条：**(a)** 实机截图；**(b)** `LocalState\reactor-startup.log` 里那行 `BACKDROP`。日志侧确认过：`ReactorLog` 里 Info 及以上才落盘、文件就是 `ApplicationData.Current.LocalFolder\reactor-startup.log`、1 MB 轮转，而 `BACKDROP` 那行正是 `Info` 级别。行格式：

```
BACKDROP <档位>: OS <build> | acrylicApi <y/n> | mica <y/n> | transparent <y/n> | batterySaver <y/n> | highContrast <y/n> | active <…>
```

`mica` 那一位是 `MicaSupported(build)` 的判定结果，`batterySaver` / `highContrast` 是系统会把材质降级的那两种状态 —— 读到 `mica y` 但屏幕上没材质，就要往后两位看是不是被系统关了。

## 4. 本批**没有**铺卡片背景，以及为什么

WinUI 2.8 的资源键集合里没有 WinUI 3 那套 Fluent 颜色令牌（`CardBackgroundFillColorDefaultBrush`、`LayerFillColorDefaultBrush` 这一族），而框架的 `ThemeResource.Brush()` 在**查不到键时返回透明笔刷、不抛**（同族代码里是 `?? new SolidColorBrush(Colors.Transparent)`）。于是 `.Background(Theme.CardBackground)` 在这里等于"画了个寂寞"，还会盖掉底下的材质层。层级因此全靠**间距 + 小标题**：区块间距 20px、标题 20px/600、区块内 8px、行内 6px（`Section` / `Page`，`MainComponent.cs:305-315`）。

> 取证口径要说实话：为了验证"WinUI 2 里没有这些键"，我用剥掉 NUL 的方式 grep 了入仓的 WinUI 2 `.appx`，连 `ButtonBackground`、`XamlControlsResources` 这些必然存在的键都是 0 命中 —— **PRI 是压缩的，这条 grep 不构成证据**。所以结论按保守写法用：代码不依赖这些刷子，两种情况下都不会画错。

## 5. alpha.13 的修饰器缺口（本批踩到的）

`Reactor.Uwp` 的 `ElementExtensions` 面比 WinUI 3 那版核心包**小**。本批实际撞到的两个：

- `.HeadingLevel(...)` —— **没有**。第一次发布就是死在这：`MainComponent.cs(306,22): error CS1061: "TextBlockElement"未包含"HeadingLevel"的定义`。已删掉调用，代价是读屏拿不到标题层级。
- `.CornerRadius(...)` —— **没有**。所以没有圆角卡片这条视觉。

有一条**自我纠正**要记下：一开始我用 `grep -oE 'static [A-Za-z]+(<T>)? Name('` 扫这份清单，据此断定 UWP 版连 `Foreground` / `Background` / `Padding` 都没有。那个模式匹配不到 `static T Padding<T>(this …)` 这种"泛型返回值在前"的签名，是**我的 grep 写错，不是包缺东西**。改对模式后，真缺的只有上面两个。`Foreground(Theme.SecondaryText)` 这类次级文本因此照写。

标题字号没有走 `ApplyStyle("SubtitleTextBlockStyle")`：那条路径要在 `Application.Current.Resources` 里查到同名样式键才有效，查不到时框架只记一条警告、什么都不画（`ElementExtensions.ApplyNamedStyle`），本机又没有 XAML 可对着看 ⇒ 用确定生效的显式 20/600。

## 6. 材质三档故意不落盘

`MaterialPicker` 的选择不写进 `LocalState\settings.txt`。那个文件是**插件进程的把手文件**（`statusToast` / `encapReturn` / `autoProbe` 那一族），为一个个观感开关引入 read-modify-write 不值当，写坏一行等于一整批实验臂失效。重启回默认（云母）。这三档的真正用处是**当场对比**：`无` 那一档用来分清"材质压根没上"和"材质上了但被内容层盖住"这两种不同的失败。界面化那 15 个把手是 Docs/17 计划表里的独立一项，不在本批。

## 7. 构建取证：包是被磁盘逼死的，不是被代码

第一次发布（1.0.67）报的是代码错（CS1061，见 §5）；修完代码后连续两次死在 AOT 链接：

```
LNK1318: 非意外的 PDB 错误: LIMIT (12)  …native\ClashUWP.pdb
（删掉旧 PDB 重试 →）
LNK1201: 写入程序数据库"…ClashUWP.pdb"时出错；请检查是否是磁盘空间不足、路径无效或权限不够
```

真正的原因：**D: 118 GB 用满，只剩 55 MB**，而一份 AOT PDB 要 110 MB。C# 编译和 ILC 原生编译全过了（`ClashUWP.obj` 132 MB 已生成），只差链接写 PDB。清盘后一次通过。

清的是本项目 `AppPackages\` 下 1.0.0–1.0.65 那 61 个旧包目录（每个 ~76 MB，共 4.4 GB），**保留 `ClashUWP_1.0.66.0_x64_Test`**（Docs/18 那 12 项清单要用的待装包）。删的是不可再生的历史包，经用户点头。清完：

```
D:  118G  113G  4.4G  97% /d          （重跑链接 → ok:true, 35.6 s）
ClashUWP\AppPackages\ClashUWP_1.0.67.0_x64_Test\ClashUWP_1.0.67.0_x64.msix   51,370,330 B
```

**下批判据：AOT 链接报 PDB 错，先看 `df`，别改代码。** 顺带记一下 D 盘的大头（本项目只占 8.1 G）：`/d/fluentapps` 40 G、`/d/20年以前工作` 26 G、`/d/msix打包准备` 9.3 G、`/d/云盘资料-常用` 9.2 G、**回收站 6.3 G**。

## 8. 上机验收清单（1.0.67.0）

装：双击 `ClashUWP\AppPackages\ClashUWP_1.0.67.0_x64_Test\ClashUWP_1.0.67.0_x64.msix`（先装同目录 `Dependencies\`，`Install.ps1` 那套在本机不可用）。

本批改的东西**在整机上零验证**，下面每一条都要人眼看：

1. 窗口是不是云母（能看到桌面颜色透进来）。
2. `LocalState\reactor-startup.log` 里有一行 `BACKDROP Mica: OS 26100 | acrylicApi … | mica …`；`mica y` 但屏幕上没材质 → 看 `batterySaver` / `highContrast` 是不是 `y`。
3. 左侧四个条目在、名字对、**图标不是豆腐块**（`E80F`/`E774`/`E896`/`E713`）。
4. 点侧边栏能切四页，`header` 跟着变（主页/代理/订阅/设置）。
5. pane 底部**没有**多出一条内置「设置」；左上角**没有**灰着的返回键。
6. 停在代理页等 10 秒，活动连接/节点列表还在自己刷 → 证明切页没打断轮询（这条是 §1 那句断言的验证）。
7. 切到设置页点「桌面亚克力」→ 材质肉眼变了；再点「无」→ 变回不透明背景；回主页重进 → 仍是所选档（`selectedIndex` 受控生效）。
8. 重启应用 → 材质回云母（§6 不落盘的验证）。
9. 主页三个按钮（建/重建 profile、连接、断开）仍可用；**这条要拨一次隧道，按老规矩单独点头**。
10. 代理页三个 mode 按钮 + 点组 + 点节点仍能选中并生效。
11. 订阅页粘贴 URL → 括号提示消失 → 「拉取并启用」；「更新当前订阅」「重新加载配置」「刷新列表」各点一次。
12. 设置页「诊断内核」「查看配置」「立即刷新」「查看日志」各一次，日志面板能滚。
